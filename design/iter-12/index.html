4.1 GET /api/admin/users（搜索 + 分页）定夺①②③ 载体
项口径（推荐，随基线定案）
参数search（用户名子串，大小写不敏感，%/_ 转义字面量，trim 后空串 = 不筛选）· limit（默认 20；1~100，越界 422）· offset（默认 0；<0 → 422）——参数名与默认值即此定案
响应兼容策略默认形状零变化：不传 limit/offset/search 任一参数 → 返回纯列表（全量，ORDER BY created_at, id 不变）——现状消费方（AdminView 旧逻辑/19 用例）零感知；传任一参数 → 分页信封
信封结构{ "items": [ …10 字段同现状… ], "total": 过滤后总数, "limit": 生效值, "offset": 生效值（钳制后） }
越界语义服务端钳制到最后一页：total>0 且 offset ≥ total → offset = floor((total-1)/limit)*limit，返回最后一页数据 + 真实 total；total=0 → items: [] 空页（前端渲染空态，非错误）（§8-②）
排序固定 created_at, id（现状；用户表不提供排序参数——零回退且无新增面）

4.2 GET /api/admin/usage（分页 + 排序后端化；筛选沿用）定夺①②③⑥ 载体
项口径（推荐，随基线定案）
筛选参数（沿用）user_id / date_from / date_to 语义与现状零变化（仅这三参数出现 = 纯列表 + 现状默认序 day DESC, username——既有用量测试形态零改动）
