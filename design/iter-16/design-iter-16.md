## 1. 范围与不做

- **做**：触点①手动压缩入口全规格（菜单加法项位置与理由 / 执行中态会话级标识 / toast 三态 + 409 提示逐字定稿 / 前端消费规则）；触点② admin 遥测视图压缩卡全规格（iter-15 遥测面板加法扩展：压缩次数 + 平均降幅 + 缺失态 + 成本口径注记）；样件文案逐字登记表（v1.4.10 B 唯一来源）；API 口径章节定案（`POST /api/chat/compact` 四语义 + `GET /api/admin/telemetry` 加法扩展）；REQ-003/004/005/012/016/026 + REQ-038 零回退映射（逐条对既有走查编号）；走查清单 44 条（三断言面 + 双主题）。
- **不做**（登记防膨胀）：主对话面任何触达（消息流/输入区/工具卡/顶区零新增元素——压缩不改变界面展示口径，CHG-010 定夺⑥「原文永久在库、界面恒全量展示」的自然推论）；「已压缩」常驻会话标记（无用户行动价值、增状态面；压缩效果可观测归 admin 卡）；压缩进度百分比（摘要为单次调用无中间进度可报，spinner 不定态 = 铁律 5 不造进度）；压缩前确认弹窗（可逆操作——原文零删除，沿「解封直接生效/导出无确认」先例）；每日压缩明细表（次数/降幅为窗口级聚合即 REQ-041 验收面，逐日下钻留 B2+ 候选不入本期）；design/proto 不同步（iter-1 核心闭环原型定位，压缩对其不可见，沿 CHG-010 影响评估口径）；移动端（CHG-007 让位定序）。

## 2. 触点①：手动压缩入口（REQ-040，侧栏列表项「···」菜单加法项）

### 2.1 菜单项位置与形态（定夺①）

| 项 | 口径（随基线定案） |
|---|---|
| 载体 | SessionListItem 既有 `DropdownMenu` 的 items 数组**加法一项**——`{ key: 'compact', label: '压缩上下文' }`；组件零改动（danger/disabled/reason/separator 均为既有字段） |
| 位置 | **「导出会话」之后、danger 分隔线之前**（常规组末位）。菜单终态 = [重命名 / 导出会话 / **压缩上下文** / ──分隔线── / 删除] |
| 位置理由 | ① 语义分组：重命名 = 标题编辑（最高频保持首位）；导出/压缩 = 会话内容级**非破坏**操作相邻；删除 = 唯一不可逆项，维持既有分隔线独占末段——不为压缩新增第二条分隔线（菜单碎片化）；② 压缩安全可逆（原文永久在库，定夺⑥）不属 danger 组、无需确认；③ 不置首位（不打断既有肌肉记忆：重命名/导出/删除的既有走查 6/8/9/10 位置断言全部零变化） |
| 项形态 | 纯文本项（现菜单项无 icon，保持一致）；高 32px、13px `--c-text-1`、hover `--c-hover-bg`（iter-11 §2.3 既有规格）；「压缩上下文」5 字 13px ≈ 65px + padding 20px < min-width 148px → **面板宽度不变**（走查条 16 几何断言） |
| 交互规格 | 全部引用 iter-11 §2 专章不重造：外点吞击关闭 / Esc 焦点回触发钮 / ↑↓ 循环含新项、跳过禁用 / 互斥 / 滚动关闭 / 右对齐上翻 / z-40 |
| 禁用态两种 | ① corrupted 会话：disabled + title「无法读取的会话不可压缩」（corrupted 不参与组装，REQ-033 异常分支；与重命名禁用同哲学，走查条 7 延伸）；② 压缩执行中：disabled + title「压缩中」（防重复点击，§2.3）。**不按轮数禁用**——前端不持有 R 参数口径（服务端 config），无需压缩语义由服务端返回（单一链路，走查条 27） |

### 2.2 点击后的执行中态（定夺②：会话级进行中标识 = 列表项 pill 插槽）

点击「压缩上下文」→ 菜单立即关闭（DropdownMenu pick 既有行为：关菜单 + 焦点回触发钮）→ 前端置该会话 compacting 态 → POST `/api/chat/compact`。

| 项 | 规格 |
|---|---|
| 会话级标识 | 该列表项 pill 插槽渲染**「压缩中」胶囊**：10px spinner（currentColor，工具步骤卡运行中徽章同款 11px 家族缩 10px 适配 pill 行高）+ 文案「压缩中」11px；`--c-primary-l` 底 + `--c-primary` 字 + r-full + padding 1px 8px——**pill.cut（生成中断）同规格参数、色组合借工具步骤卡「运行中」徽章语义族**（进行中 = primary 族，components.md v1.4 既有登记形态，零新令牌） |
| pill 优先级 | 压缩中（当前进行中）> 无法读取（corrupted，但 corrupted 不可触发压缩，实际互斥）> 生成中断（历史状态）——v-else-if 链首位插入 |
| 进度语义 | 不定态 spinner，**不显示百分比**——摘要为单次非流式调用（30s 护栏），无中间进度可报；编造进度违铁律 5 |
| 持续时长 | 自请求发出起，至响应到达（成功/无需压缩/失败/409 任一终态）清除；正常 1~10s、上限约 30s（摘要超时护栏） |
| 防重复 | compacting 期间该会话菜单「压缩上下文」项 disabled + title「压缩中」；其余项（重命名/导出/删除）不受影响 |
| 不做全局态 | 无模态、无全局 banner、不阻塞侧栏其他操作——压缩是会话级轻操作（沿 admin ban/unban toast 先例：操作反馈走 toast，过程标识挂在对象上） |

### 2.3 toast 结果反馈（三态 + 409，逐字定稿见 §3 登记表）

| 终态 | toast | 形态 |
|---|---|---|
| 成功 | `✓ 上下文压缩完成：中段历史已摘要，聊天记录不受影响` | **success 变体**（绿字，✓ 前缀调用方拼入——沿 SettingsForm 改密/注销成功先例）；3s 自动消失 |
| 无需压缩 | `当前会话无需压缩：历史还短` | 默认白字 toast；3s |
| 失败 | `压缩失败，请稍后再试` | 默认白字 toast；3s；涵盖摘要调用失败/超时/上游 4xx·5xx/网络（用户无需区分子类——诊断细节在 warning 日志与 compress 行，沿 iter-14 D1「error 与 timeout 共用一句」哲学） |
| 409 生成中 | `该会话正在生成回复，暂不能压缩，请等生成完成后再试` | 默认白字 toast；3s；文案 = 服务端 409 message 逐字（前端直接呈现，两路径同文） |

- **成功 toast 不呈现 token 数字（定夺③，决策记录）**：REQ-041 口径 `tokens_after` = 压缩后首次 step=1 上游调用 usage **懒回填**——同步响应时刻未测得；`tokens_before` 对新会话/无遥测记录会话为 NULL。只给半截数字（有 before 无 after）误导用户以为 after=0，违铁律 5「不造数」精神；压缩效果度量（前后规模/降幅）的观测面归 admin 压缩卡（REQ-041），用户侧 toast 只给**确定性事实**：① 完成了 ② 机制（摘要）③ 无数据损失（「聊天记录不受影响」= 定夺⑥原文永久在库的用户语言）。
- **409 由服务端唯一判定（定夺④，决策记录）**：前端**不预判**本地 generating 状态、照常发请求。理由：多设备场景下本地 controller 状态覆盖不了「另一设备正在该会话生成」的竞态，服务端回合登记是唯一权威；前端预判只会形成两条提示链路（前端拦截 + 409 toast）且口径必须一致——单一链路最简且可断言。
- 主对话面零触达：压缩成功/失败对消息流/输入区/工具卡/顶区零新增元素；当前会话被压缩后视图零变化（界面口径 = 库内全文，定夺⑥）。

## 4. 触点②：admin 遥测视图压缩卡（REQ-041，iter-15 遥测面板加法扩展）

### 4.1 位置与形态（定夺⑤：双卡并排区与卡 D 之间的全宽卡 E）

| 项 | 口径（随基线定案） |
|---|---|
| 载体 | iter-15 遥测面板（AdminView 第三 tab）**加法一张卡**：面板序列 = 工具行 → 卡 A 每日成本估算 → 双卡并排（B 缓存命中率 / C 工具用量）→ **卡 E 上下文压缩（新增，全宽）** → 卡 D 按日成本明细 |
| 位置理由 | ① 双卡并排区不扩为三卡——B 卡含四列表格、三卡等宽（≈340px）表格挤压且动 B/C 形态，违加法纪律；② 阅读序 = 成本总览（A）→ 率与效果（B/C/E）→ 明细账本（D 殿后），压缩效果属「率与效果」层置于明细之前；③ 全宽卡承载双大数值 + 副题 + kv-row 注记宽度从容 |
| 容器 | 统计卡家族照搬（iter-15 tel-card 同规格）：`--c-surface` + 1px `--c-border` + r-lg 12px + `--shadow-1` + padding 16px 20px；与相邻卡间距恒 16px |
| 标题区 | icon 14px `--c-text-3`（压缩/收拢形）+ 标题 C9（13px/600 `--c-text-1`）+ 副题 C10（12px `--c-text-3`，口径常驻自释——沿 iter-15 卡 B「说明常驻」哲学） |
| 双大数值 | 两列等宽栅格 gap 16px：列 1 = 次数（label C11 + 大数值 20px/600 `--c-text-1` tabular-nums + sub）；列 2 = 降幅（label C12 + 大数值 NN.N% 或缺失徽标 + sub C13）——大数值规格与 iter-15 tc-big 逐参数一致 |
| kv-row 注记 | 卡底分隔线上方 12px 区（iter-15 kv-row 同形态）：C16 逐字——一句话注解 B2 两条成本/配额口径，admin 看成本变化时自释 |
| 门禁 | 无新入口：卡 E 在遥测 tab 内，403 路由守卫 + get_admin_user 接口门禁沿用（普通用户 DOM 无节点）；零新增请求（同一 `GET /api/admin/telemetry` 响应加法字段） |

### 4.2 数值口径与三态（缺失标注语义 = REQ-025「不估算补齐」沿承）

| 态 | 触发（后端事实） | 用户所见（= 验收口径） |
|---|---|---|
| 正常 | 窗口有 compress 行且有测得行 | 次数大数值（含失败行）+ sub 成功/失败分列；降幅 NN.N% + sub 已测得/成功 |
| **缺失态**（核心异常形态） | 有 compress 行但**零测得行**（tokens_after 全 NULL——压缩后该会话再无回合、懒回填未测得） | 次数如实显示；**降幅位显「缺失」徽标 C14（不显 0%、不显 NaN）**；sub C13 显示 `已测得 0 / 成功 N`——缺失原因自释（铁律 5：未测得不估算） |
| 空态 | 窗口零 compress 行 | 大数值行整体替换为空文案 C15（12px `--c-text-3` 居中，非错误态，iter-15 卡 C 空态同族）；kv-row 注记保留 |

- **降幅聚合口径**（= REQ-041 验收 3 断言面）：`1 − Σtokens_after ÷ Σtokens_before`，**仅计 status=ok 且 before/after 均非 NULL 的行**（部分缺失口径沿 iter-15 定夺⑤哲学：只计带数据行 + 说明常驻自释，不另弹提示）；失败行（error/timeout）**只计次数、不计降幅**（REQ-041 异常分支逐字口径）。
- **0 与缺失的区分纪律**（iter-15 走查要点沿承）：降幅合法 0（压缩前后同规模）如实显 0.0%；未测得恒为「缺失」徽标——二者视觉语言不同（走查条 40）。
- **成本口径注记的归属决策（定夺⑦）**：CHG-010 要求成本聚合计入 compress 行 tokens，但**卡 A 副题逐字 T3 是 iter-15 基线零回退面，不改**；注记落卡 E kv-row（C16）——「按输入计价」出处 = CHG-010 内容 3.3「摘要 prompt 消耗以 input 计价」，「手动压缩不计回合」出处 = 定夺⑧。

## 5. API 口径（随稿定案——T3 实现依据；体例沿 design-iter-14 §6 / design-iter-15 §4）

硬门槛：既有全部端点形状零变化——turn/sessions/profiles/admin 六端点 + PUT settings + `GET /api/admin/telemetry`（iter-15 形状逐字节不动，仅加法 `compact` 键）。

### 5.1 POST /api/chat/compact（新端点 · 手动压缩）

```
POST /api/chat/compact
{ "session_id": "s_ab12" }                       ← body 仅此一字段；缺字段/非字符串 → 422

鉴权：会话 token（CurrentUser，沿回合端点同款依赖）
归属：复合主键 (user_id, session_id) 隔离——不存在或属他人一律 404（不泄露归属，REQ-040 验收 4）

→ 200 { "status": "compacted", "tokens_before": 41235 }
        成功。tokens_before = 该会话上一回合 step=1 telemetry tokens_prompt 机器实测值；
        无记录（新会话/遥测缺失）→ null（不估算）。前端不呈现该值（§2.3 决策）
→ 200 { "status": "skipped", "reason": "too_short" }
        无需压缩（总轮数 ≤ R）：零上游调用、零计费（REQ-040 验收 3：假传输层零调用断言）
→ 409 { "detail": { "code": "session_generating",
                    "message": "该会话正在生成回复，暂不能压缩，请等生成完成后再试" } }
        该会话有进行中回合（服务端回合登记判定——多设备竞态唯一权威，§2.3 定夺④）
→ 404 { "detail": { "code": "session_not_found", "message": "会话不存在" } }
→ 422 { "detail": { "code": "session_uncompactable", "message": "无法读取的会话不可压缩" } }
        corrupted 双保险（前端菜单已禁用）
→ 502 { "detail": { "code": "compact_failed", "message": "压缩失败，请稍后再试" } }
        摘要调用失败/上游 4xx·5xx/空摘要
→ 504 { "detail": { "code": "compact_failed", "message": "压缩失败，请稍后再试" } }
        摘要调用超时（30s 独立护栏，定夺⑨）。502/504 共用 code 与 message——
        用户侧失败 toast 恒为一句（C7），子类区分归 warning 日志与 compress 行 status
```

detail 对象形状沿 `sessions.py` 409 `session_schema_conflict` 先例（`{code, message}`，client.ts 既有消费链路直接支持）。

**服务端执行语义（定死）**：
- 同步执行完整管道：一级 snip + 全量 compact，**不受阈值判定约束**（REQ-040 描述口径）；摘要调用口径 = REQ-039（非流式、30s 护栏、跟随当前密钥模式、`<conversation_summary>` 包裹防注入）。
- **不计回合**（定夺⑧）：quota.py 零调用、usage_daily 零写入；tokens 仅落 telemetry。
- compress 行（REQ-041 行口径）：`kind='compress'`、`endpoint='compact'`、`turn_id=NULL`、model=摘要模型、latency_ms=摘要调用耗时、status=ok/error/timeout、tokens_prompt=摘要调用自身消耗、tokens_before=上一回合 step=1 实测值（无则 NULL）、**tokens_after=NULL 待懒回填**（该会话下一次 step=1 上游调用 usage 到达后独立短连接回填，T3 承载）。
- 失败/超时：`context_summary` 零变化（原摘要仍有效则保留，REQ-040 异常分支）；chat_sessions 会话档任何分支均零写入（REQ-039 验收 6 存储语义对手动路径同样适用）。

**前端消费规则（定死，走查条 21~27 断言面）**：

| 响应 | 前端动作 |
|---|---|
| 200 `status=compacted` | 清 compacting → success toast C5 |
| 200 `status=skipped` | 清 compacting → toast C6 |
| 409（session_generating） | 清 compacting → toast 显示服务端 message 逐字（= C8） |
| 其余非 200（404/422/5xx）与网络错误 | 清 compacting → toast C7（固定文案兜底；服务端 502/504 message 与 C7 同文，两路径同串） |
| 请求在途 | 置 compacting（pill C2 + 菜单项禁用 C3）；切换会话不 abort、toast 全局显示 |

### 5.2 GET /api/admin/telemetry 加法扩展（REQ-041 聚合面）

```
→ 200 { ...iter-15 形状逐字节零变化（window/price/today_cost/daily/tools/retention_days）...,
  "compact": {
    "count": 12,                    ← 窗口 compress 行总数（含失败行——REQ-041「失败行照常落、只计次数」）
    "count_ok": 10,
    "count_failed": 2,              ← error + timeout 行合计
    "measured": 8,                  ← status=ok 且 tokens_before/tokens_after 均非 NULL 的行数
    "tokens_before_total": 384000,  ← Σbefore（仅计测得行）
    "tokens_after_total": 122880,   ← Σafter（仅计测得行）
    "reduction_rate": 0.680000      ← 1 − Σafter/Σbefore（后端保留 6 位小数，沿 iter-15 精度口径）；
  }                                   measured=0 → null（前端显「缺失」徽标，永不显 0/NaN）
}
```

- **成本聚合口径演进（CHG-010 授权，形状零变化）**：`today_cost` 与 `daily[].cost_total` 的成本计算计入 `mode='unified'` compress 行的 `tokens_prompt × input_per_mtok ÷ 1e6`（摘要调用按输入计价，CHG-010 3.3）；自填模式 compress 行 tokens 不计成本（定夺⑥口径自然延伸）。数值口径含新行、字段形状零新增——既有 admin pytest 用例的造数不含 compress 行则数值断言零变化。
- 门禁零变化：`get_admin_user`；普通用户 403 响应体零遥测字段（含 compact 键，REQ-041 验收 4）。
- 缺失语义：compress 聚合只读已落库行；懒回填未测得 = NULL = 缺失（铁律 5），聚合层无手工修正入口。
