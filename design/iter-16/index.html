4.1 POST /api/chat/compact（新端点 · 手动压缩 · 四语义）
项口径（随基线定案）
请求POST /api/chat/compact，body { "session_id": "…" }（仅此一字段；缺字段/非字符串 → 422）；鉴权 = 会话 token（CurrentUser，沿回合端点同款依赖）
归属隔离复合主键 (user_id, session_id)——不存在或属他人一律 404（不泄露归属，REQ-040 验收 4）；普通用户正常操作、无 admin 门槛
执行语义同步执行完整管道：一级 snip + 全量 compact，不受阈值判定约束（REQ-040 描述）；摘要调用口径 = REQ-039（非流式 / 30s 独立护栏 / 跟随当前密钥模式 / <conversation_summary> 包裹防注入）
配额口径不计回合（定夺⑧）：quota.py 零调用、usage_daily 零写入；tokens 仅落 telemetry compress 行——test_quota 全套零改动复跑全绿（REQ-040 验收 1）
compress 行kind='compress' / endpoint='compact' / turn_id=NULL / model=摘要模型 / latency_ms=摘要调用耗时 / status=ok·error·timeout / tokens_prompt=摘要调用自身消耗 / tokens_before=该会话上一回合 step=1 telemetry 实测值（无记录 null）/ tokens_after=NULL 待懒回填（该会话下一次 step=1 上游调用 usage 到达后独立短连接回填，失败不阻塞不补造——T3 承载）
失败语义摘要调用失败/超时/空摘要/上游 4xx·5xx → 502/504；context_summary 零变化（原摘要仍有效则保留，REQ-040 异常分支）；chat_sessions 会话档任何分支均零写入（REQ-039 验收 6 对手动路径同样适用）；warning 日志 + compress 行如实记 status（铁律 5）

编号问题选项与推荐（样件已按推荐落形）理由 / 备选（未采纳留档）
① 菜单加法项位置（CHG-010 定夺④已定「侧栏列表项「···」菜单项」，菜单内位置为设计参数） 推荐：「导出会话」之后、danger 分隔线之前（常规组末位）；菜单终态 = 重命名 / 导出会话 / 压缩上下文 / ── / 删除 语义分组：重命名 = 标题编辑（最高频保持首位肌肉记忆）；导出/压缩 = 会话内容级非破坏操作相邻；删除唯一不可逆维持分隔线独占末段。压缩安全可逆（原文永久在库）不属 danger、不加确认、不新增第二条分隔线。
备选 A（未采纳）：置首位——打断重命名首位的既有走查 6/8 位置断言与肌肉记忆；备选 B（未采纳）：压缩与删除之间再加分隔线——菜单碎片化，常规组内无隔离必要
② 执行中态形态（菜单已关闭后的反馈载体；摘要调用上限约 30s，无反馈不可接受） 推荐：列表项 pill 插槽「压缩中」胶囊（10px spinner + 11px，primary-l/primary = 工具步骤卡「运行中」徽章语义族）+ 菜单项禁用防重复 会话级操作的反馈挂在对象上（沿 admin ban 操作 toast + 对象状态先例）；pill 插槽为既有（broken/cut 两款在前），规格参数照搬零新令牌；不定态 spinner = 单次调用无中间进度可报（编造进度违铁律 5）。
备选 A（未采纳）：仅 toast 结束反馈、无执行中标识——最长 30s 无反馈用户疑挂死；备选 B（未采纳）：全局 banner/模态——会话级轻操作不配全局打扰面
③ 成功 toast 是否呈现效果数字（任务书留白：「含效果信息？如压缩前后规模，口径来自 API 返回，你定呈现」） 推荐：不呈现 token 数字，只给确定性事实（C5「上下文压缩完成：中段历史已摘要，聊天记录不受影响」） tokens_after = 压缩后首次 step=1 上游调用的懒回填实测值——同步响应时刻未测得；tokens_before 对新会话/无遥测记录会话为 NULL；只给半截数字误导（看似 after=0），违铁律 5 不造数精神。效果度量（前后规模/降幅）的观测面归 admin 卡 E（REQ-041 承载），用户侧不重复。「聊天记录不受影响」= 定夺⑥原文永久在库的用户语言，回答用户最担心的「会不会丢消息」。
备选（未采纳）：显示 tokens_before——半截数字，且对新会话恒缺省，文案分支增多断言面不稳
④ 409 生成中的判定链路（前端是否预判本地 generating 状态） 推荐：服务端唯一判定，前端零预判照发请求；409 到达 → 清执行中态 + toast C8（= 服务端 message 逐字） 多设备场景本地 controller 状态覆盖不了「另一设备正在该会话生成」的竞态，服务端回合登记是唯一权威；前端预判只收窄窗口不消除竞态，且形成两条提示链路（前端拦截 + 409 toast）口径必须一致——单一链路最简可断言。
备选（未采纳）：前端本地生成中直接拦截不发请求——双链路维护 + 多设备竞态仍靠 409 兜底，复杂度不减
⑤ admin 压缩卡位置（iter-15 遥测面板加法扩展的落位） 推荐：双卡并排区与卡 D 之间的全宽卡 E；面板序列 = 工具行 → A → B/C 并排 → E → D 双卡并排区不扩三卡——B 卡含四列表格，三卡等宽 ≈340px 表格挤压且动 B/C 形态违加法纪律；阅读序 = 成本总览（A）→ 率与效果（B/C/E）→ 明细账本（D 殿后）；全宽承载双大数值 + 副题 + kv-row 注记从容。
备选 A（未采纳）：B/C/E 三卡并排——挤压 + 动既有形态；备选 B（未采纳）：并入卡 A——压缩效果是独立观测维度，混入成本卡破坏卡 A 逐字零回退面
⑥ 降幅的部分缺失口径（tokens_after 懒回填：部分行测得、部分行 NULL 时如何聚合） 推荐：仅计测得行（status=ok 且双侧非 NULL）+ 副题常驻自释「降幅仅统计压缩前后均测得的压缩」；零测得行 → 显「缺失」徽标（永不显 0） 与 iter-15 缓存命中率定夺⑤同哲学（只计带数据行 + 说明常驻，不另弹提示）；统一 key 数据永远可见可算，懒回填未完成行不污染分母；「已测得 N / 成功 M」sub 行如实暴露测得面（铁律 5 不藏数据）。
备选（未采纳）：任一行未测得即整个窗口显缺失——过严，长会话压缩效果永远不可见，违背 B2「效果可验证」目标
⑦ 成本口径含 compress 行 tokens 的注记位置（CHG-010 要求计入，是否注记与注记落位由设计判断） 推荐：注记，落卡 E kv-row（C16）；卡 A 副题与既有逐字面零改动 成本数值因 compress 行加入而上升，admin 无注记会不明所以——注记必要；卡 A 副题 T3 是 iter-15 基线逐字零回退面不可改，注记落新卡 E 底部 kv-row（iter-15 既有形态），一句话同时自释「按输入计价」（CHG-010 3.3）与「手动压缩不计回合」（定夺⑧）两条 B2 口径。
备选（未采纳）：不注记——成本口径静默变化，部署者对账困惑；备选（未采纳）：改卡 A 副题加一句——破 iter-15 逐字断言面，零回退纪律不容
