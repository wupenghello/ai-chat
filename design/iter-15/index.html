硬门槛：既有 admin 六端点（users/ban/unban/quota/usage/overview）+ PUT /api/admin/settings 形状零变化， 既有 admin pytest 用例零改动复跑全绿（REQ-038 验收 1）。遥测为新增一个只读聚合端点（加法扩展，不触既有端点）。
4.1 GET /api/admin/telemetry（新端点 · 只读聚合）
项口径（推荐，随基线定案）
参数days（整数 1~90，默认 7；越界/非整数 → 422）——时间窗 = 截至服务器本地今日（quota.today() 口径，与 usage_daily.day / telemetry.day 同源，不引入时区换算）的近 N 个自然日
门禁get_admin_user 依赖（与既有六端点同一依赖）——非 admin → 403，响应体不含任何遥测字段（REQ-038 验收 3）；普通用户界面侧无遥测入口（tab 在 AdminView 内，403 路由守卫已覆盖，前端零新增守卫）
数据源telemetry 表（迁移 v8，REQ-037）：kind='llm' 行供成本与命中率（mode 区分 unified/self）；kind='tool' 行供工具用量；全部机器聚合，无手工修正入口（铁律 5）
成本聚合仅 mode='unified' 的 llm 行：cost_input = Σtokens_prompt × input_per_mtok ÷ 1e6；output / cache_hit 同法（cache_hit 的 tokens 基数 = Σcache_hit_tokens）；cost_total = 三项和；后端保留 6 位小数，响应为数值（非字符串）；单价未配置 → price.configured=false 且全部 cost_* 字段为 null（tokens 字段照常如实返回）
命中率聚合cache_rate = Σcache_hit_tokens ÷ (Σhit + Σmiss)（该日带字段行聚合；NULL 行不参与）；整天无带字段行 → cache_rate: null（前端显「缺失」，不显 0）；tokens 分项为 null 时 JSON 输出 null（不是 0、不是缺字段）
工具聚合GROUP BY tool_name, status：count = 行数；avg_duration_ms = 均值四舍五入整数；排序固定 tool_name ASC, status ASC（确定性，走查可断言）
缺失语义有数据的日子逐日列出、无数据日不出现在 daily 数组（前端以窗口天数比对判定缺口 → 琥珀行 T23）；遥测写失败行不补造（REQ-037 口径）——聚合层只见已落库行
