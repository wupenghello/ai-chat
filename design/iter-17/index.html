      "source_session_id": "s_c7d2",            ← 抽取来源会话；用户手工编辑后归 null（§4.2）

      "created_at": "2026-08-19 21:04:11",
      "updated_at": "2026-08-19 21:04:11"
    }, …
  ],
  "memory_enabled": true,
  "injection_preview": "<user_memory>\n以下是关于用户的长期记忆（自动从历史对话抽取），回复时作为用户背景参考：\n1. …\n</user_memory>" | null
}

口径（定死）：
  entries 数组顺序 = 注入组装顺序 = 预览编号顺序（一一对应；前端不排序）
  injection_preview = 回合组装同一拼装函数的组装时点逐字取值（「看到的就是注入的」，定夺⑨）；
  memory_enabled=0 或 entries 为空 → injection_preview = null（没有注入发生，不呈现注入物——铁律 5）
  上限口径：entries ≤ 30 条、单条 ≤ 150 字（T0 收紧定案，verify §3；本端点只读，截断在抽取侧）
→ 失败：网络/5xx → 前端落加载失败态（M28/M29，§4.5 消费规则）

PUT /api/memory/{id}

  memory_enabled=0 → 注入跳过且后台扫描跳过（不新抽取）；存量记忆保留，重新启用即恢复注入。
  停用零回退：组装与基线 v7 口径逐字段等价（REQ-042 验收 2，pytest 面，不在本稿呈现）。
4.4 无 POST 端点（有意边界，登记防膨胀）
CHG-011 内容 3.7 API 框架仅四端点（GET / PUT / DELETE / PUT settings）——不提供手动新增记忆：记忆的唯一来源 = 对话自动抽取（审核稿「自动沉淀」叙事）， 「手工编辑」仅指对既有抽取条目的改写（PUT 后来源归零，M12 分支）；手动新增入口如未来需要走 CHG。本期 UI 无「添加记忆」按钮（走查条 34 反向断言）。

编号问题选项与推荐（样件已按推荐落形）理由 / 备选（未采纳留档）
① 分区内布局（列表与预览的排布） 推荐：自上而下 = 标题+说明 → 停用开关行 → 记忆列表 → 注入预览（折叠置底） 开关 = 分区级总闸置顶（其态决定下方列表/预览的呈现分支）；列表 = 主任务居中；预览 30 条满载约 4.8k 字符，置底折叠不挤列表首屏。
备选 A（未采纳）：预览置顶常显（「注入可见」优先）——列表主任务被挤压，可见性不因折叠受损；备选 B（未采纳）：列表/预览左右分栏——面板有效宽 ≈500px，分栏后两列均过窄
② 编辑交互形态（行内 vs 模态） 推荐：条目卡内行内 textarea（prompt-ta 家族 + 150 字计数 + 取消/保存，Esc 取消） 单字段短文本（≤150 字）行内最轻；不新增 z-110 层叠消费者（弹窗内层模态面不膨胀）；行内重命名（iter-11#8）与对话设置提示词（textarea + 显式保存）双先例的组合。
备选（未采纳）：编辑模态——多一层遮罩与 Esc 栈节点，收益为零；模态适合多字段表单（档案编辑五字段先例），单字段不配
③ 删除确认形态（强确认模态 vs 行内确认 vs 无确认） 推荐：ConfirmModal 现状组件照搬（360px + danger-solid「删除」+ Esc/遮罩取消） 删除不可逆需确认；档案删除已用 ConfirmModal（同重量级先例，组件零改动）；单条记忆非账号级不可逆，不配 DeleteAccountModal 密码强确认。
备选 A（未采纳）：行内二次点击确认（「再点一次删除」）——无组件先例、误触保护弱；备选 B（未采纳）：无确认直接删（沿「解封/导出无确认」哲学）——删除不可逆且记忆为自动沉淀产物，误删恢复依赖下次抽取，成本不对称
④ 停用态列表呈现（灰显 vs 收起 vs 照常可操作） 推荐：灰显（opacity .45）+ 条目操作冻结 + 停用通知条 停用 = AI 不使用记忆，管理操作也无即时可见效果——冻结避免「改了但不生效」困惑；信息仍可见（可检视性不回退，审核稿「记忆可检视」承诺）；重启用即恢复，状态转换一步完成。
备选 A（未采纳）：收起为一句话——可检视性回退，重启用后用户需重新定位；备选 B（未采纳）：照常可操作——停用态下编辑/删除的生效语义需额外解释面（「改了要启用才注入」），认知成本高
⑤ 注入预览形态（折叠/常显/代码样式） 推荐：可折叠（默认折叠）+ 代码块样式（code-bg/code-text 族令牌，mono 12px，pre-wrap，max-height 220px 内滚） 代码块深底 = 「这是逐字注入物，不是界面文案」的语义自释（令牌语义现成，零新增）；默认折叠守住列表首屏；「所见即所注」由展开即满足（REQ-043 验收 4 是取值一致性，不是常显性）。
备选 A（未采纳）：常显——满载预览把列表挤出首屏；备选 B（未采纳）：普通文本样式——与界面文案混同，用户难辨「这段会真的发给模型」
⑥ 元信息呈现粒度（来源会话名 / 时间 / 模型显示哪些） 推荐：显示来源（自动抽取 ·「会话名」/ 手工编辑）+ 更新日期；不显示模型 来源会话名给可追溯性（「这条是哪次对话沉淀的」），ellipsis + title 防长标题破行；日期到「日」精度足够（记忆为天级节奏）；模型名对用户零行动价值（技术细节），且自填模式下模型名随档案变化徒增噪音。
备选 A（未采纳）：显示模型——信息密度升、行动价值零；备选 B（未采纳）：不显会话名只显「自动抽取」——追溯性损失，来源会话名为记忆可信度的证据链
⑦ toast 文案三态（保存/删除/停用） 推荐：保存 M30 / 删除 M31 / 停用 M32 + 启用 M33（成功态 success 绿字 ✓ 前缀）+ 三失败态 M34~M36；成功文案统一带「下一回合生效」时效标注 「下一回合生效」是用户唯一需要知道的时效事实（注入读库时点），常驻 toast 自释、免生「为什么 AI 这轮还不知道」的疑惑；失败态一句兜底不暴露技术细节（REQ-007 精神）；✓ + success 变体沿 SettingsForm 改密/注销成功先例。
备选（未采纳）：成功 toast 不带时效——用户当回合测试「AI 记得吗」必失望，先问后答不如先说
⑧ 记忆编辑态是否纳入未保存拦截（dirty 判定） 推荐：不纳入——关闭弹窗 = 取消记忆编辑；dirty 判定链与拦截文案字节级零变化 REQ-028 dirty 拦截文案「（系统提示词 / 密码输入）」是既有逐字面——纳入记忆编辑必改文案，破零回退纪律；记忆编辑为行内瞬态（≤150 字短文本），关闭即弃的损失与行内重命名同量级（iter-11 先例亦不拦截）；Esc 链已给编辑态专属取消位（条 20），误关损失有显式退出路径兜底。
备选（未采纳）：纳入——拦截哲学更彻底，但代价 = 既有逐字面改写 + dirty 判定链扩展，收益不对称
