2修改密码（REQ-021 主流程 + 异常分支，可交互）

输入旧密码 + 新密码 + 确认新密码 → 验证旧密码通过后更新密码哈希 → 除当前设备外的其他设备会话 token 全部失效（当前设备保持登录，定夺 ①）。 异常：旧密码错误提示「旧密码错误」不修改；新密码不达强度 / 两次不一致 / 必填缺失 → 行内提示不提交。

5适用性说明（不适用项注明，v1.4.4 口径）

项结论依据
移动端 ≤480px 适配不适用：设置页维持桌面优先，不做窄屏断点spec 兼容条款（CEO 定 2026-08-15，随 design-iter-6 基线批准）：仅登录/注册两页承诺 ≤480px
密码强度计 / 复杂度实时指示条不做：用行内文案提示「至少 8 位，含字母与数字」，满足 spec「不达强度提示不提交」最小口径components.md 无强度计模式；不新增组件
注销冷却期 / 导出数据 / 封禁注销兜底不在范围：spec REQ-021 未含；如需另立项spec 最小口径
样件凭据本稿用户名「猫南北」、密码 mm2026 均为演示数据；线上旧密码校验 / 密码哈希更新 / 会话 token 失效 / 账号数据删除全部由后端处理，前端不落地明文凭据铁律 5「度量数据只允许机器采集」+ REQ-021 数据口径

6令牌与组件使用说明

本稿零新增令牌；账号管理为既有令牌与设置页表单 / 模态确认 / 提示条语法的组合。
项结论
色值 全部取自 tokens.md v1.3/v1.3.1（浅色 + 暗色 + 前景/实底拆分族 + on-dark 族），本稿零新增、零裸色值（文档外壳沿惯例用浅色原值；产品组件一律 var() 引用语义令牌，含阴影/焦点环/遮罩/深底 toast）。无需 design-system 令牌变更。
组件模式 设置页分区 / 表单字段 / 密码显隐 / 分段控件 / 模态确认（危险实底）/ 表单级横幅 = components.md v1.0 + design-iter-5/6 既有模式；登录页 = design-iter-6 基线引用；走查清单格式 = design-iter-8。
基调变更（CEO 2026-08-16 拍板）：应用外壳反转为「侧栏灰 --c-bg + 正文白 --c-surface」（原 iter-1~8 为「侧栏白 + 正文灰」），令牌值不变、仅换「哪里用哪个令牌」；新增 app-shell + side-rail 外壳组件承载此布局。
新增形态三项（纯既有令牌组合，建议随本基线批准后补登记 components.md——资产沉淀，不涉令牌批准，沿 iter-7 KeyModeCard / iter-8 数据表格惯例）： ① 注销危险区（danger-l 底 + danger 描边/文字 + 危险实底按钮）；② 成功横幅（subtle-bg 底 + success 描边/标题，改密成功反馈）；③ 应用外壳（app-shell + side-rail）（侧栏灰底 + 正文白底，DeepSeek 管理页式分层）。
success 浅底令牌 components.md 无 success 浅底令牌（tokens 仅 --c-success 前景）。改密成功横幅沿用 iter-8 同款组合：subtle-bg 底 + success 描边/标题（两模式对比度均 AA）。本稿不提新增 --c-success-l（保持零令牌变更）。
字号/间距/圆角/阴影/动效 全部在 tokens 既定值域内（正文 14px、辅助 12/13px、模态标题 17px、分区 label 13px、输入 36px、按钮 32/36px 阶梯、间距 8 基准栅格、圆角 r-sm/r-md/r-lg、阴影 shadow-1/2/3、过渡 .15s ease、按压 scale .98）。

编号问题（iter-9.md T0 原文）推荐方案（本稿样件已按此落形）理由 / 备选（未采纳留档）
① 改密成功后当前设备是否强制重新登录（spec 主流程默认「除当前外其他设备失效」→ 当前设备保持登录；需确认） 当前设备保持登录，不强制重登：更新密码哈希后，除当前设备外的其他设备会话 token 全部失效（需重新登录）；当前设备会话不受影响，改密成功后仅提示「其他设备已退出登录」。 与 spec 主流程字面一致（「除当前设备外的其他设备会话 token 全部失效」）；改密是安全操作但高频，强制重登体验重且无安全增益（当前设备已通过旧密码验证，可信）。
备选（未采纳）：全部设备强制重登（更保守但违反 spec 字面、体验重）。
② 注销二次确认的形态与文案（输入密码二次确认的具体措辞与层级） 强确认模态 + 输入登录密码：模态标题「注销账号？」，正文「将删除账号与全部云端数据（会话、供应商档案、密钥等）。此操作不可恢复，删除后无法找回。」，密码字段 label「输入登录密码确认」，确认按钮危险实底「永久注销账号」；密码为空 disabled。 spec 明确「输入登录密码二次确认」；删除不可恢复需最强确认——密码输入是账号体系内最重的确认（优于 checkbox / 输入 DELETE 文案，无额外 UI 模式）；「永久」强调不可逆。
备选（未采纳）：checkbox 确认（太弱，配不上不可恢复）；输入「DELETE」文本（英文词对中文用户不友好）。
③ 账号区在设置页的呈现口径（独立「账号」区块 vs 页签 vs 列表项） 独立「账号」区块：延续既有设置页分区结构（settings-section-label），作为「外观」「供应商档案」之后的第三个区块，置于页尾；内含修改密码表单 + 注销危险区两个子区。 账号管理低频，分区即可满足发现性与信息架构；零新增信息架构，最小改动延续 iter-5 设置页基线。
备选（未采纳）：设置页顶部页签（重构整个设置页信息架构，超最小口径，且账号仅两项内容不足以撑起一个页签）；独立「账号」路由页面（spec 明确「设置内」，且拆分过多跳）。
④ 注销后跳转与「账号已删除」提示的具体形态 跳登录页 + 深底成功绿 toast：注销成功 → 清除本地会话/凭据 → 跳 /login（空表单）；登录页顶部深底 toast「✓ 账号已删除，再见」（--success-on-dark #4CC38A，3s）。 登出/账号终结是用户自主的正常终态，用轻量 toast 即可、不阻塞登录页；成功绿（success-on-dark）区分于封禁等异常态的琥珀 warning；清除本地数据防止残留。
备选（未采纳）：登录页常驻成功横幅（重，账号已删无后续操作）；弹窗（阻断登录流程）。
