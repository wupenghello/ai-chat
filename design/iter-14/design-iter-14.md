## 1. 范围与不做

- **不做**（登记防膨胀）：**真实天气工具任何 UI——已定案不纳入本迭代（CEO 2026-08-18 范围确认），B1 排期再议，本稿零涉及**；回答内上标/角标联动（备砍序 a 直接按基线形态定案为纯来源列表卡，联动交互留暂缓池 B1+ 候选）；用户侧搜索开关（不存在此需求——admin 总开关 × 档案开关两级已覆盖）；admin 页面其他区域（统计卡/用户列表/用量列表/分页 = iter-12 基线零翻案，本轮仅增开关行一处）；移动端（CHG-007 让位定序）；输入区 / 侧栏 / 消息流既有语言（iter-11/13 基线零翻案）。

## 2. 引用来源卡 UI 规格（定夺① = 4.8-6 载体，「原型即需求」本体）

AI 消息流内**次级面板家族新成员**：容器 = `--c-subtle-bg`（#FAFBFC / #24272E）+ 1px `--c-border` + 圆角 **10px**（同工具步骤卡，components.md v1.2 家族值）；头部行常显可点击；**无状态机、无运行中态**（卡只在 tool.result 到达时出现，出生即终态）。

### 2.1 承载与位置（blocks 数据面零结构改动）

| 项 | 口径（随基线定案） |
|---|---|
| 数据承载 | **tool_result 结构化扩展**：`ToolResultBlock` 增可选字段 `sources?: SourceItem[]`（不新增 block 段类型）。`SourceItem = { title: string, url: string, snippet?: string, site_name?: string, date_published?: string }`（title/url 必有，其余可选——两家搜索 API 归一化形状，§2.3） |
| 渲染规则 | tool_call 段渲染工具卡后，若其**配对 tool_result** 含非空 `sources` 且 `status=ok` → **紧随渲染引用来源卡**（沿 MessageBubble 既有配对机制，渲染层派生，blocks 数组零新增段类型） |
| 位置 | **紧跟 search 工具卡之后、回答首段文本之前**（blocks 顺序 = 事件顺序的自然结果：tool.result 先于回答 text.delta 到达）。流式期间 tool.result 到达即现（回答尚在生成，用户先见来源——核验前置），后续文本段自然追加其后，零重排规则 |
| 不渲染条件 | `sources` 为空 / 缺失 / `status ≠ ok`（失败、超时、空结果一律无卡——失败时回答的降级标注由 §3 引导条承载） |
| 落库与透传 | sources 随 tool_result 段进 blocks 落库（PUT 整档透传保真，既有机制零改动）；老客户端读新会话：未知字段忽略、不崩（iter-13 §3.1 未知段/字段防御口径同精神）；新客户端读老会话：无 sources → 无卡 |
| 适配面 | **零新增**：导出 / 复制 / 搜索索引沿「工具内容非正文」口径，sources 不入正文（REQ-013/016/CHG-003 零波及）——这是选 tool_result 扩展而非新 block 类型的核心收益 |
| 条数防御 | 后端按结果条数参数（§7，5 条）保证 `sources.length ≤ 5`；前端渲染前 `slice(0, 5)` 兜底，头部条数 = 实际渲染条数 |

> **iter-13 §3.5 预留叙述修订登记**：该稿预留契约为「挂回答末尾」，本稿定夺为「回答之前（tool.result 位置）」。理由：① blocks 顺序 = 事件顺序的铁律零例外（末尾方案需「turn.end 定型时重排追加」特殊规则）；② 核验前置——搜索完成即可见来源，回答流式生成期间用户已能确认「AI 真的搜了、来源是什么」（REQ-035 用户故事「可核验」的流式兑现）；③ 主流产品同位先例（来源列表在回答上方）。差异随本稿基线登记，不回改 iter-13 已基线文档。

### 2.2 卡片形态与折叠

| 项 | 规格 |
|---|---|
| 头部行（常显） | button 语义，同工具卡：icon 14px `--c-text-3`（书签形）+ 名称「引用来源」13px/500 `--c-text-1` + 「· N 条」12px `--c-text-3` tabular-nums + chevron 12px（.15s 旋转 180°）；行高 ≥36px（padding 7px 12px）、hover `--c-hover-bg`、`aria-expanded` 同步、Enter/Space 原生、`:focus-visible` 内嵌 2px `--c-focus-ring` |
| 头部文案（逐字） | **`引用来源 · 5 条`**（「·」两侧各一空格；N = tabular-nums）——v1.4.10 B 断言面 |
| 默认态 | **默认折叠**（出生即折叠，无 R1 展开期——与工具卡 R2/R3「终态折叠、历史折叠」精神一致）；无自动折叠规则（无运行中态可转）；历史消息恒折叠 |

### 2.3 条目形态与归一化字段（两家来源承载，缺字段不塌）

| 字段 | 必有 | 渲染 | 缺失降级 |
|---|---|---|---|
| `title` | 是 | 标题行：13px/500 `--c-primary` 链接（hover 下划线 + `--c-primary-h`），`href = url`、`target="_blank" rel="noopener noreferrer"`；textContent 直排**不进 Markdown 管线**（防注入，沿「工具内容不进管线」口径） | 缺 → `hostname`（前端自 url 计算） |
| `url` | 是 | 不直接展示全串（href 承载；元信息行用 hostname 表达来源身份） | —（必有） |
| `site_name` | 否 | 元信息行首段 | 缺 → `hostname` 兜底 |
| `date_published` | 否 | 元信息行次段（`·` 分隔），**原样透传不重排格式**（YYYY-MM-DD 或来源原文） | 缺 → 该段连同分隔点一并省略 |
| `snippet` | 否 | 片段行：12px/1.5 `--c-text-2`，**两行 line-clamp 截断**（超长不破卡；全文看原站） | 缺 → 不渲染（仅标题+元信息紧凑形态） |

- 元信息行整行 12px `--c-text-3`、上距 2px；片段行上距 4px；条目内边距 8px 0。
- **两家实测形状的承载验证**（原型双数据源切换）：**Tavily 型** = 结构化 content 长摘要（片段行承载、两行截断）+ 无 siteName（hostname 兜底）；**博查型** = siteName + datePublished 富元数据（元信息行完整）+ 短片段。同一卡片字段集合优雅承载两种，缺字段不塌、不出现空块或悬挂分隔点。
- 对比度登记：条目标题 `--c-primary` 链接组合沿全站 `.md a` 既有口径（浅 4.1:1 / 暗 4.9:1，13px/500 非正文强调元素，非 REQ-017 正文约束对象）；片段 `--c-text-2` 沿 v1.3 既有结论（≥4.5:1）。

## 3. 搜索降级与空结果文案定稿（逐字，v1.4.10 B 断言面）

| # | 文案（逐字） | 触发 | 形态与位置 |
|---|---|---|---|
| D1 | **`搜索未成功，以下为模型直接回答`** | search 工具 tool.result(status=error/timeout)，且消息仍有后续文本段（直答） | **warning 引导条**：`--c-warning-l` 底 + 左缘 3px `--c-warning` + 13px `--c-warning` 字，padding 8px 12px、圆角 8px（r-md）；位置 = 失败工具卡之后、直答首段之前；**渲染层派生不落库**（规则确定性：历史重渲染一致；派生态先例 = 工具卡「已中断」） |
| D2 | **`未搜到相关内容`** | 搜索结果为空（后端组装的 tool.result `result` 文本，逐字定死） | 搜索工具卡「完成」态结果区内原样渲染（后端拥有文案、前端零处理——与截断标注 `[结果超长，已截断]` 同口径）；**无引用卡、无引导条**；模型据该 result 如实回答、不编造来源（REQ-035 异常分支） |
| D3 | **`引用来源 · N 条`** | 引用卡头部（§2.2） | — |
| D4 | admin 关闭搜索 | 工具不在注册表 → 模型直答 | **零 UI**：无 search 卡、无引用卡、无引导条、无任何提示（「模型不知其存在」无感降级，REQ-035 异常分支 / 验收 3 用户侧走查口径） |
| D5 | admin toast：**`已开启联网搜索`** / **`已关闭联网搜索`** | 开关操作成功（§4） | 现有 AppToast（深底）承载 |
| D6 | admin key 缺失附注：**`搜索密钥未配置：请在服务端 backend/.env 中设置 AI_CHAT_SEARCH_KEY 并重启后端，开启后才会生效`** | `search_key_configured=false`（§6.1） | 开关行说明区 warning 色（`--c-warning`）替换常显说明；开关仍可操作（状态先存，key 配置后即生效） |
| D7 | 档案开关 hint：**`关闭后，使用此档案的对话不携带工具（如联网搜索），AI 直接回答`** | 档案模态（§5） | 12px `--c-text-3` |

- error 与 timeout 共用 D1 一句：用户无需区分 429 与超时（诊断详情在工具卡结果区，展开可见）；「回合继续、降级直答」由引导条 + 直答文本共同表达。
- 导出 / 复制不含引导条（非文本段，与 max-steps pill 同口径：过程标注不入正文导出）。

## 6. API 口径（随稿定案——T2 实现依据；体例沿 design-iter-12 §4）

硬门槛：**既有 admin / profiles 相关用例零改动通过**（加法扩展策略，iter-12 先例）。

### 6.1 admin 开关存取

```
GET /api/admin/overview
→ 200 { ...既有字段零变化...,
       "search_enabled": true,          ← 新增（加法字段）
       "search_key_configured": true }  ← 新增（只报有无，不泄露 key 内容）

PUT /api/admin/settings
{ "search_enabled": false }
→ 200 { "search_enabled": false }
```

| 项 | 口径 |
|---|---|
| 读取 | 并入 overview 响应（加法扩展，现有消费方零感知）；AdminView 既有 loadMeta 拉取，**零新增请求** |
| 写入 | 新端点 `PUT /api/admin/settings`（B1 服务端配置面板可扩展复用）；非 admin 403；body 缺字段 / 非布尔 422；幂等（重复 PUT 同值 200） |
| key 与开关分离 | key = `.env` 部署配置（`AI_CHAT_SEARCH_KEY`，改需重启）；开关 = 落库运行时状态（即时生效）；`search 实际注册 = admin 开关 ∧ key 已配置`（key 缺失时开关状态可存但工具不注册） |
| 默认值 | `search_enabled = true`（默认开，REQ-025 口径） |

### 6.2 运行时生效语义（关闭 = 模型不知其存在）

| 项 | 口径 |
|---|---|
| 存储 | 开关值落 SQLite（KV 表实现 T2 定，稿不锁表结构）；读取点位 = **回合受理时实时读**（验收锚 =「PUT 后下一回合生效」，无需重启） |
| 生效边界 | 正在生成的回合不受影响（注册判定在回合开始时一次性完成）；PUT 后**新回合**即生效 |
| 关闭语义链 | 注册表过滤 search（tools_for_user 挂点）→ 上游请求 tools 定义不含 search → 模型不知其存在 → 用户侧直答无感（§3 D4）——payload 断言 = T2 pytest（MockTransport 捕获，plans T2 验收 3） |
| 开关断言矩阵 | admin 开关 × 档案「支持工具」× key 模式三态组合断言随 plans T2 验收执行（admin 关·档案开 → tools 无 search；admin 开·档案关 → 无 tools；admin 开·档案开/统一 key → 含 search；统一 key 恒开不参与变化）——本稿登记引用，不重复展开 |

### 6.3 profiles 扩展（档案开关数据面）

```
GET /api/profiles
→ 200 [ { ...既有字段零变化..., "tools_enabled": true } ]   ← 加法字段

POST /api/profiles        { "name":…, "base_url":…, "model":…, "api_key":… }              ← 老形状：tools_enabled 缺省 = true
POST /api/profiles        { …, "tools_enabled": false }                                   ← 新形状：显式关
PUT /api/profiles/{id}    { …, "tools_enabled": false }                                   ← 编辑：显式传值覆盖
PUT /api/profiles/{id}    { … }                                                            ← 未传 = 沿用原值（老前端零破坏）
```

- payload `tools_enabled` **可选布尔**：缺省 = 新建 true / 编辑沿用原值（与 api_key「留空 = 沿用」同精神；老客户端不带此字段不 422）。
- 响应 `ServerProfile` 加 `tools_enabled: bool`（加法，现有用例零改动）。

### 6.4 SSE / blocks 数据面扩展（引用卡来源）

```
data: {"type":"tool.result","tool_call_id":"c_1","status":"ok",
       "result":"…结果摘要 + 来源列表文本（给模型）…","duration_ms":2380,
       "sources":[ {"title":"…","url":"https://…","snippet":"…","site_name":"…","date_published":"2026-08-12"}, … ]}
```

- `tool.result` 事件负载增**可选 `sources` 数组**（§2.1 归一化形状）；`result` 文本与 `sources` 数组 = 后端同一搜索结果的两个视角（模型消费文本、前端消费结构化列表，REQ-035 主流程 3 组装口径的落形）。
- 前端：配对挂卡后渲染引用卡（§2.1）；落库随 tool_result 段透传；**未知负载字段忽略**（老前端遇 sources 不崩，iter-13 §4.1 前向兼容精神）。
- 老客户端读新会话：sources 字段被忽略、仅少渲染引用卡（窗口期已知边界，不丢数据）。

## 7. 微参数表 + 4.8-10 定夺值随稿登记

| 参数 | 候选 | 推荐（随基线定案） | 理由 |
|---|---|---|---|
| search 单工具超时 | 8 / 10 / 15 s | **10s** | Tavily 常规响应 1~3s、长尾约 8s；交互式等待体感上限约 10s（用户盯 spinner 超过即怀疑挂死）；超时路径已兜底（降级直答不崩）。8s 对深度搜索/慢查询偏紧误杀，15s 悬挂感强无增益 |

| 引用卡折叠默认 | 默认折叠 / 默认展开 | **默认折叠** | 引用卡是核验资产非过程演示（与工具卡 R2/R3「终态折叠」同精神）；5 条展开约 300px+，默认展开淹没回答；头部行「引用来源 · N 条」一行承载存在感，要看再点 |
