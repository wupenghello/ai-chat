2工具步骤卡规格（REQ-032 · 定夺⑤=4.8-5 载体，「原型即需求」）

AI 消息流内的次级面板：一条 assistant 消息的 blocks 中，每个 tool_call 段渲染一张卡（与文本段按 blocks 顺序混排）。 结构 = 头部行（常显，点击折叠/展开）+ 展开区（参数块 + 结果块）。全部既有令牌组合，零新增令牌。
2.1 状态徽章四态 + 派生中断态tool.result 的 status 映射；中断态为渲染派生态（非协议状态）
状态来源徽章规格（20px 胶囊 · r-full · 12px/500）语义与后续
运行中tool.call 到达--c-primary-l 底 + --c-primary 字 + 11px 双色环 spinner（currentColor，.8s linear）；浅 #F0F4FF/#3370FF · 暗 #1D2740/#5C8DFF工具执行中（受单工具超时约束）；展开区结果块显示占位「（等待结果…）」
完成tool.result(status=ok)--c-surface 底 + --c-success 字 + 1px --c-border + ✓ icon；浅 #FFFFFF/#1A9E5C · 暗 #1E2026/#4CC38A结果挂载（截断后文本原样渲染）；头部行显示耗时
失败tool.result(status=error)--c-danger-l 底 + --c-danger 字 + ✕ icon；浅 #FDECEA/#D93025 · 暗 #361B18/#FF8073错误结果回填模型，回合继续，模型可降级直答（REQ-030 异常分支）
超时tool.result(status=timeout)--c-warning-l 底 + --c-warning 字 + 时钟 icon；浅 #FFF7E8/#B45309 · 暗 #38290F/#EDA23B单工具超时到期取消执行；与「失败」分色保留诊断信息（参数错 vs 时间到）；回合继续
已中断（派生）tool_call 段无匹配 tool_result 段（回合 aborted / 上游中断 / 用户停止后落库）--c-hover-bg 底 + --c-text-2 字 + 「—」icon（中性，同「已停止生成」pill 语言）；浅 #F2F3F5/#646A73 · 暗 #262930/#A2A9B6渲染规则：工具步骤不得以「运行中」徽章留存历史（spinner 冻结 = 误导）；展开区结果块显示「（回合中断，未获得结果）」
为什么超时用 warning 而非 danger：失败（error）= 确定性拒绝（参数/权限/未注册，重试同样失败）；超时（timeout）= 时效性失败（服务慢，重试可能成功）——语义色分档沿全站 success/warning/danger 三族既有语言，与「生成中断」（warning）同族的时效语义一致。

3.1 读路径规则（渲染器输入侧）
规则口径

blocks 顺序渲染文本段（.md）与工具卡按数组顺序原样呈现，不重排、不合并跨工具卡的文本段（保留生成时序感——「先说一句 → 调工具 → 继续答」）；段间 8px（.blocks gap），消息间 20px 沿用
写侧用户消息恒 string（无工具语义，现状不变）；assistant 消息 v2 起用 blocks（至少一段）；回合事件流组装规则见 §4.1（text.delta 归并当前文本段 / 工具事件后 text.delta 开新段）
文本段管线仅 text 段进 markdown-it + DOMPurify（REQ-011 改写口径）；工具参数与结果不进 Markdown 管线（卡内 pre-wrap/mono 直排）——代码块样式沿 design-iter-3 基线引用不重画
防御blocks 空数组 / 未知段类型：不渲染该段、不抛错（沿 parseSse 前向兼容精神）；写侧保证至少一段（T2 断言）
3.2 同流呈现规则（v1/v2 混排 = REQ-032 验收 1 的界面面）
场景呈现
同会话 v1 + v2 消息混排文本部分视觉零差异：同字号/行高/气泡规则/间距，无任何格式标记或分隔（m1/m2 与 m5+ 对照；「标注消息格式」开关为走查辅助件，产品无此 UI）

搜索（REQ-016 定案）blocks 消息取文本段拼接参与索引；工具调用参数与结果不入索引（500ms 口径不变）
