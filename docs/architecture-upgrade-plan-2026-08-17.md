# ai-chat 架构升级：Claude Code 借鉴清单与分批建议（CEO 审核稿）

> 状态：**待 CEO 审核**。批准 = 方向批准；需求登记（分析师走 CHG）与排期（PM）在批准后进行，本轮不动任何代码与需求文档。
> 输入：前端/后端代码探查 ×2、需求分析师流程意见、规划员分批压测（含 file:line 取证），2026-08-17。

## 一、背景与目的

CEO 判断：ai-chat 目前是「调 API 拿结果再打印」的聊天封装，没有自己的东西；Claude Code 是按生产级 agent 架构设计的系统。本稿把 Claude Code 的架构要素逐条对照 ai-chat 代码现状，筛出**适合我们的、可实现的**部分，分批排布供 CEO 审核。

**战略叙述**：A+B+C 完成后，ai-chat = 「带工具、带记忆、成本可观测的 agent 产品」——这就是区别于纯封装的「自己的东西」。

## 二、现状快照（代码事实）

### 前端（Vue 3.5 + TS + Pinia + Vite，src/ 约 11,700 行，Vitest 254 用例）

- 状态管理：Pinia 5 store 分层清晰；聊天核心 `src/stores/sessions.ts`，每会话独立 AbortController + 生成纪元防竞态。
- 消息模型：`ChatMessage` content **纯 string**，无 tool_calls、无分段 blocks（`src/api/client.ts`）。
- 上下文管理：`buildContext()` = system 提示词 + **最近 20 轮硬截断**，无 token 计数、无压缩；组装在前端。
- 流式：手写 `parseSse()` 只认 `delta.content`，未知帧静默跳过（协议扩展点，新后端+旧前端天然前向兼容）；已有 `upstream_interrupted` 自定义帧先例。
- 渲染：markdown-it+DOMPurify，无高亮、无工具步骤 UI；已有 Message 五态状态机、版本分支可复用。
- 无任何：工具 UI、记忆、埋点、插件机制。

### 后端（Python 3.12 + FastAPI + SQLite + httpx，无 AI SDK、无 service 层，pytest 139 用例）

- 「账号 + 会话云同步 + 流式转发」三件套：`backend/app/routers/proxy.py` 对上游 SSE 逐字节透传（旁路已累积全流供 usage 提取，「解析再重组」雏形已在），配额在端点入口拦截；**对对话内容零感知**。
- 无 provider 适配层：统一 key（DeepSeek）/自填（任意 OpenAI 兼容端点，含 GLM）；裸 httpx，**零 function calling**。
- SQLite 5 表 + `PRAGMA user_version` 迁移体系；配额先查后计（30/500/全站 2000 每日）；`usage_daily` 仅按日 requests+tokens（无明细/延迟/成本/缓存命中）。
- 可沿用地基：贯通前后的 SSE 管线（含中断帧）、配额拦截点、usage 旁路采集、共享 httpx 池、带版本迁移的 SQLite。

**结论**：agent 化的核心工程量在**后端从零建运行时**，前端是协议与渲染升级；改造面集中（client.ts / sessions.ts / MessageBubble.vue / proxy.py / quota.py）、测试底子好（MockTransport 假上游夹具现成），无架构级阻断。

|---|---|---|---|---|
| **A1** | Agent 地基 | Σ10 = M+L+L（顶格，备回退项） | T0 设计基线（SSE 事件协议 v2 / blocks 模型 / 组装迁服务端边界）；T1 后端：消息级模型+归一化、工具网关、ReAct 循环、SSE 解析重组（~100-150 行新模块）、配额回合化、内置演示工具；T2 前端：blocks+读时归一化、协议扩展、工具步骤 UI | 2 步工具回合事件序逐帧断言；步数上限/工具超时/断连取消各有 pytest；配额第 6 回合被拦且未抵上游；老 string 会话渲染零回退；254 用例回归全绿 |

**移动端**：不并入本方向；建议 agent UI 形态稳定（约 B1 后）再做，避免二次适配；一个迭代不同时塞两条主线。

## 五、不采纳 / 暂缓项及理由

1. **投机执行（CoW overlay 预执行）**：无「先审批后执行」场景，无对应用户故事；其「乐观 UI」思想已部分体现在流式渲染。不排期。
2. **完整 shell 沙箱 / BashTool 式 20 项检测**：我们不出 shell 工具；安全投入收窄到工具网关基线（A1/A2）。远期若加代码执行工具再立专项。
3. **自研状态管理**：Pinia 是 Vue 官方对等物，重复造轮子零收益。
4. **split-pane 多 agent 并行 UI**：等 D1 验证价值后再议。

1. **方向与七期顺序**（A1→A2→B1→B2→C→D1→D2）是否批准。
2. **联网搜索并入**：放弃单独做，A1 先以内置演示工具验证循环，A2 交付真实搜索。

4. **搜索必须自建**的确认：统一 key 是 DeepSeek（无自带联网搜索），必须后端接第三方搜索 API（Tavily/博查/SearXNG）；具体选型 A2 T0 定夺。
5. **配额语义改「按回合」**：一回合 N 次内部调用计 1 次、tokens 如实累计、步数上限兜底。
6. **自填模式降级策略**：任意 OpenAI 兼容端点 ≠ 必支持 tools，需档案级能力开关或自动去 tools 重发（CHG 定夺项，现只需知悉）。
7. **升级窗口期边界**：多设备新旧客户端并存时，旧端保存可能抹掉新格式工具步骤（LWW 语义，不做服务端 schema 校验）——接受为已知边界并登记。
