# 搜索供应商对比评估：Tavily vs 博查（Bocha）

- **日期**：2026-08-22
- **性质**：暂缓池条目「搜索供应商对比评估」的评估报告（spec.md:1113，CEO 2026-08-18 指示「后期专门弄个迭代测试 Tavily 和博查的优劣」，2026-08-22 指示先做）
- **数据来源**：① 2026-08-18 同题冒烟对照记录（spec.md:1113 留档）；② 两家官网/文档/云市场公开资料（2026-08-22 查证）；③ 现网代码事实（`backend/app/search.py`）；④ 大模型厂商联网搜索补充对比（2026-08-22 CEO 提出后补查，见 §7）；⑤ 开源项目 Agent-Reach 查证（2026-08-22 CEO 提出后补查，见 §8）
- **范围限制（如实声明）**：本地 `.env` 未配搜索 key、本地遥测库 0 行（v0.5.0 未上服务器，无 A2 真实运行数据）——本报告为**桌面评估**，非新一轮真实 A/B 实测。真实运行数据积累后的复测脚本见 §5。

## 1. 结论（先说结果）

**维持 Tavily 为默认，不切换**；但明确「中文强时效场景」为博查的优势区，切换成本已锁定在 S 级（改 `search.py` 常量与归一化字段映射），建议等 v0.5.0 上服务器、真实运行数据积累后再按 §5 脚本做正名性复测。理由：

1. **成本**：Tavily 明显便宜（PAYG 约 $8/千次 ≈ ¥57，且免费 1,000 次/月）vs 博查约 ¥108~36/千次（渠道报价混乱：阿里云市场 ¥108/千次折扣价、第三方文档 ¥0.036/次 ≈ ¥36/千次，官方阶梯需登录控制台核实）。
2. **产品质量**：两家风格互补而非全面差距——博查中文源与新鲜度占优，Tavily 结构化摘要完整；当前用户量（自部署、小团队）不足以让中文新鲜度差异成为决定性痛点。
3. **集成现状**：`search.py` 归一化层是按 Tavily 字段写的（title/url/content/published_date），博查字段（siteName/datePublished/summary/snippet）同样可映射到五字段 SourceItem 形态，切换无架构障碍，确认了「S 级」评估。

## 2. 六维度对比表

| 维度 | Tavily | 博查 Bocha | 判定 |
|---|---|---|---|
| 中文质量 | 英文/通用质量高；中文源覆盖一般 | 国产引擎，中文源覆盖好（近千亿网页+生态内容源） | **博查优**（冒烟已见） |
| 新鲜度 | topic=news + days 时间窗（现网已用，CHG-008） | freshness 参数（如 oneYear）+ 中文新闻生态 | **博查略优**（中文新闻源；英文时效 Tavily news 足够） |
| 元数据完整度 | title/url/content（长摘要）/published_date（部分结果有）；无 site_name | snippet/summary/siteName/siteIcon/datePublished，字段更全 | **博查略优**（siteName 免前端 hostname 兜底；summary 长摘要与 Tavily content 对等） |
| 延迟 | 冒烟未记录显著问题；10s 工具超时（design-iter-14 §7）余量充足 | 未见公开 SLA 数据；国内访问链路对国内部署更友好 | **无实测数据，平**（复测项 §5） |
| 成本 | 免费 1,000 credits/月；PAYG $0.008/次 ≈ ¥57/千次；包月更低（$0.0075→0.005/次） | 约 ¥36~108/千次（渠道报价不一，官方阶梯待核实）；有免费资源包（控制台领取） | **Tavily 优**（免费额度 + 单价下限更低） |
| 稳定性 | SaaS、API 成熟（credit 体系、429 降级路径现网已覆盖） | SaaS、日调用 3000 万次、据称现金流转正；国内 Region 合规友好、数据不出海 | **平**（博查合规面占优：域名出境 vs 国产合规） |

## 3. 与现网集成的适配性核对

- `search.py:49-50` 固定域白名单 `api.tavily.com` → 切换 = 改 `TAVILY_HOST/URL` 为 `api.bochaai.com`；
- `normalize_results()`（search.py:87-110）字段映射：博查 `siteName→title 兜底`、`summary/snippet→snippet`、`datePublished→date_published` 均可直接落五字段 SourceItem，`siteName` 还能消掉前端 hostname 兜底（design-iter-14 §2.3）；
- `days` 参数（topic=news）→ 博查 `freshness`，语义可换算（N 天 → noLimit/oneDay/oneWeek/oneMonth 等档位取最近档，**有精度损失**：博查是档位制非任意天数——切换时需在 design 定夺映射规则）；
- 计费遥测（REQ-037 工具维度）与 admin 开关零改动。

**确认：切换成本 S 级成立**，唯一需要设计定夺的是 days→freshness 档位映射。

## 4. 决策建议

| 场景 | 建议 |
|---|---|
| 当前（自部署、小用量、成本敏感） | **维持 Tavily**：免费 1,000 次/月大概率覆盖现有用量，零成本 |
| 上线后中文用户占比高、新闻/时效类查询占比高且 Tavily 中文质量投诉 | 切博查（走一条小 CHG：days→freshness 映射定夺 + 白名单域改换 + 归一化适配） |
| 国内服务器部署遇出境调用受限/延迟劣化 | 切博查（合规与链路优势） |

## 5. 上线后复测脚本（正名性验证，择机执行）

1. 取 20 个同题查询（中文时效 10 + 中文综合 5 + 英文综合 5），双供应商各跑一遍（两家 key 已备存服务器端 `.env`）；
2. 记录：结果条数、`date_published` 有效率、p50/p95 延迟（telemetry `tool` 行现成）、来源域去重数、摘要完整度人工评分 1~5；
3. 以 telemetry 真实运行数据（REQ-037）为输入复盘本表 §2 的「无实测」两格；
4. 若博查在中文时效面显著胜出且成本差 ≤ ¥50/千次量级可接受 → 启动切换 CHG。

## 7. 补充：大模型厂商联网搜索（2026-08-22 CEO 提出后补查）

CEO 指出 GLM（智谱）、Qwen（阿里）、火山（字节）等大模型厂商均有联网搜索服务。查证结论：**这是一类不同形态的竞品，且部分可能优于博查**。

### 7.1 与 Tavily/博查的本质区别

| | Tavily / 博查 | 大模型厂商联网搜索 |
|---|---|---|
| 定位 | 独立「给 AI 用的搜索」服务商，搜索即主业，厂商中立 | 平台生态附属工具，设计意图是配合自家模型 |
| 形态 | 独立 REST API，返回结构化结果，接任意模型 | 两种：① 独立 REST API（智谱 search_pro、百炼联网搜索工具，可直接接）② 深度耦合插件（火山方舟联网插件——调用其模型时服务端自动挂载，搜索与生成一体） |
| 与 ai-chat 架构适配 | 完全适配（网关后一个工具，全链路自控） | ①类可接；②类**冲突**：搜索决策权交还厂商，工具步骤卡/引用来源卡/遥测（REQ-037）等自建面拿不到或残缺，与 ReAct 自主循环（REQ-030）架构相悖 |
| 长期稳定性 | 搜索是主业，接口演进以独立工具用户为先 | 演进以自家平台优先，作为独立工具使用的连续性有平台绑定风险 |
| key/账目 | 各一家 | 再增一家 key/账目（现为 DeepSeek 统一 key + Tavily 搜索 key） |

### 7.2 价格与能力查证（2026-08-22）

| 服务 | 价格 | 免费额度 | 备注 |
|---|---|---|---|
| 阿里百炼联网搜索（北京 Region） | **¥4/千次** | — | 新加坡 Region ¥73/千次（出境价）；网页抓取工具限时免费；另有 MCP 版 ¥29/千次（前 2,000 次免费） |
| 火山方舟联网内容插件 | **¥4/千次**（按量日结） | **2 万次/月** | 形态为方舟模型插件，独立接入适配性待核实 |
| 智谱 search_pro | **¥10/千次** | GLM Coding Plan 套餐内含（Lite 100 / Pro 1,000 / Max 4,000 次/月） | 夸克垂直源版 search_pro_quark ¥50/千次；独立 REST API 形态 |
| （参照）博查 | ¥36~108/千次 | 控制台资源包 | §2 |
| （参照）Tavily | ≈¥57/千次 | 1,000 次/月 | §2 |

中文质量：三家背靠自家内容生态（智谱有夸克源、字节百度系索引），中文覆盖与新鲜度至少不输博查，且国内 Region 数据不出海。

### 7.3 对本评估结论的影响

1. **博查的备选地位被部分挤掉**：若「中文质量 + 价格 + 合规」是切换动因，百炼（¥4/千次，独立 API 形态）优先级高于博查。
2. **真正的候选格局变为**：Tavily（免费额度 + 全球源 + 主业厂商 + 零迁移成本）vs 国内大厂搜索（¥4~10/千次 + 中文强 + 平台绑定风险）。
3. **维持 §1 结论不变**：当前仍以 Tavily 为默认（免费额度覆盖现用量，切换无收益）；上线后若触发切换动因，候选顺位改为：**百炼联网搜索 > 博查 > 智谱 search_pro**（火山因插件形态与架构冲突暂不列）。
4. §5 复测脚本若执行，A/B 对象建议改为 **Tavily vs 百炼**（博查降为观察项）。

## 8. 补充：开源项目 Agent-Reach（2026-08-22 CEO 提出后查证）

CEO 提出 GitHub 开源项目 [Agent-Reach](https://github.com/Panniantong/agent-reach)（Panniantong/agent-reach）。查证结论：**与 §2/§7 的搜索供应商不在同一层，不构成 ai-chat 搜索供应商候选**。

### 8.1 它是什么

MIT 开源的「能力层」CLI（Python）：给**本地编程 Agent**（Claude Code / Cursor 等能执行 shell 的 Agent）装上读全网能力。核心价值不在自研读取，而在**选型 + 路由**——每平台维护「首选 + 备选」后端列表（如 B 站 yt-dlp 被风控后自动切 bili-cli），配 `doctor` 体检命令。覆盖：网页（Jina Reader）/ YouTube 字幕 / B 站 / V2EX / 雪球零配置可读；Twitter / 小红书 / Reddit / Instagram 靠浏览器登录态或 Cookie 解锁；**全网搜索走 Exa 的免费 MCP 通道（免 key）**。曾登 GitHub trending 日榜第一，单人维护、迭代活跃。

### 8.2 与搜索供应商的四维差异

| | Tavily / 博查 / 百炼 | Agent-Reach |
|---|---|---|
| 形态 | 服务端 REST API，产品后端直接调用 | 本地 CLI + skill 文件，Agent 执行 shell 命令 |
| 服务对象 | 产品全体终端用户（ai-chat 多用户） | 个人开发者本机的 Agent（单机单人） |
| 搜索质量 | 自建索引 / 结构化结果，付费 SLA | 搜索仅其一隅，走 Exa 社区免费通道 |
| 合规 | 正规 API 计费，可用量遥测 | 大量渠道靠 Cookie / 登录态 / 绕风控，README 自警「有封号风险，用小号」 |

### 8.3 为什么 ai-chat 不能采用

ai-chat 搜索跑在多用户服务端，走工具网关治理链（固定域白名单 / SSRF 校验 / key 服务端注入 / 遥测计费，REQ-031/035/037）。Agent-Reach 的三个基本设定分别冲突：跑 shell 命令 ↔ 注入防护；浏览器 Cookie 复用 ↔ 多用户隔离；多后端路由 ↔ 出网白名单治理。Cookie 渠道等于把 SearXNG「聚合抓取合规灰区」放大（README 明示封号风险）；CHG-007 不做 SearXNG 的理由（单人公司容量撑不住运维与质量波动）对其同样成立——它的功能本质就是持续追赶平台封堵，维护负担是其特性。

### 8.4 对本项目的参考价值

1. **本地开发环境可自用**：若希望本地编程 Agent 读 Twitter / 小红书 / B 站字幕，安装它划算（免费 / doctor 自检 / MIT）——属个人工具决策，不入 ai-chat 产品。
2. **路由模式可借鉴**：「每渠道首选 + 备选有序后端 + 体检命令」与本项目「主备切换 S 级」思路同构；将来若做多搜索供应商冗余，此模式值得参考。
3. **Exa 进入视野但暂不扩池**：其搜索走 Exa（社区免费 MCP 通道，产品化需另购正式 key）；是否纳入对比池待真实切换动因出现再议，本次不扩。

### 8.5 评判

作为个人 Agent 工具箱是好项目；作为 ai-chat 搜索供应商候选不成立（层不对、形态不对、合规不对）。本报告候选格局维持 §1/§7.3 不变：**Tavily 默认 + 百炼优先备选**。
