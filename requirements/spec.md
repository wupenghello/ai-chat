## 1. 产品概述

ai-chat 为多个用户提供 AI 对话服务：任何人可注册账号使用，对话经自建后端统一接入第三方大模型 API（OpenAI 兼容协议，DeepSeek/GLM），支持流式输出的多轮连贯对话；会话数据存储在服务端，同一账号多设备数据一致。产品定位为**多用户自部署 Web 服务**——单人即可部署、供多人注册使用的自托管服务。本产品不做 RAG/知识库与联网搜索（暂缓，见想法池）。

**架构决策（2026-08-15 CEO 拍板；CHG-004 已批准（2026-08-15，req-baseline-v3））**：应用为**前后端分离架构**——前端 Vue3 + TS + Vite 不变；新增 **Python FastAPI 后端**，职责：① 用户账号体系（注册/登录/会话管理，用户名+密码自管，不依赖第三方登录；**不保留未登录本地模式，必须登录**）；② API 密钥统一管理与服务端代管，**双模式**——默认服务端统一 key（配额内免费额度），高级设置允许用户自填 key 存服务端并解锁更高配额；③ OpenAI 兼容流式请求的代理转发；④ 用户数据（会话/供应商档案）云端存储。公开注册前提下，滥用防护与用量配额为上线必要条件（REQ-024，P0）；服务治理由 Web 管理后台承担（REQ-025，P1）。

**仓库布局（2026-08-15 CEO 拍板，CHG-004 实施层细化）**：同仓库 monorepo——后端代码置于本仓库新增 `backend/` 目录（Python/FastAPI，独立依赖文件与 lockfile，.gitignore 排除 `__pycache__`/`.venv`）；前端代码保持根目录现状不动；`docker-compose.yml` 放仓库根目录统一编排。不另建独立后端仓库、不用 submodule。

> 决策历史：2026-08-15（req-baseline-v1）曾拍板「纯前端应用直连第三方 API，不自建后端」；同日 CEO 决策升级为自建 FastAPI 后端（CHG-004），原决策由上文替换，原文存于变更历史（changes.md / git 历史）。

## 2. 用户故事

### REQ-001 发送消息并流式接收回复

- **用户故事**：作为用户，我要在输入框输入文本并发送，以便获得 AI 的回答，且回答以流式方式逐步显示，以便我不必等待完整生成。
- **描述**：对话主界面的核心交互：文本输入框 + 发送按钮 + 消息展示区。AI 回复以打字机效果流式渲染。
- **主流程**：
  1. 用户在输入框输入文本（支持多行）
  2. 点击发送按钮或按回车（Shift+Enter 换行）
  3. 用户消息立即显示在消息区，输入框清空
  4. 消息区出现该会话的 AI 回复气泡，内容随流式返回逐步渲染
  5. 流式结束后，回复气泡标记为完成
- **异常分支**：
  - 输入为空或仅含空白字符：发送按钮不可用，点击无动作，不发出请求
  - 发送时上一条回复仍在生成中：禁用发送（或提示等待），不并发请求
  - 网络失败 / API 报错 / 超时：该 AI 气泡显示明确错误提示（含错误类型），并提供"重试"入口；用户已发出的消息保留在消息区，不丢失
  - 流式中断：已收到的部分内容保留显示，并标注"生成中断"
- **验收标准**：
  - 输入"你好"并发送后，1 秒内用户消息出现在消息区
  - 收到首个流式数据块后 200ms 内，回复气泡开始显示内容
  - 回复过程中界面无需整体刷新，历史消息不重排闪烁
  - 发送空字符串 / 纯空格：无请求发出，无新气泡产生
  - 断网状态下发送：3 秒内出现含错误提示的气泡，且提供重试；重试成功后正常流式显示
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）

### REQ-002 多轮上下文记忆

- **用户故事**：作为用户，我要 AI 记住我在本会话中说过的话，以便进行多轮连贯对话而不必每次重复背景。
- **描述**：每次请求将本会话的历史消息一并发给 API，使 AI 回复与上文连贯。上下文组装规则：**系统提示词（如有，见 REQ-008）+ 最近 20 轮（最多 40 条消息）**；更早轮次仅存本地，不参与请求。
- **主流程**：
  1. 用户发送第 N 条消息
  2. 系统按上述规则组装请求上下文（系统提示词 + 最近 20 轮）
  3. AI 回复与上文指代、事实保持连贯
- **异常分支**：
  - 会话消息超出 20 轮：自动截断，仅携带最近 20 轮，不报错、不中断对话；被截断轮次仍完整保留在本地与界面中
- **验收标准**：
  - 连续对话测试：第 1 轮告知"我叫小明"，第 5 轮问"我叫什么"，AI 回答包含"小明"
  - 第 10 轮对话的请求中可观测到包含此前轮次的消息（通过请求体或日志验证）
  - 第 30 轮对话的请求体中仅包含最近 20 轮消息，对话仍正常进行，无报错；界面仍可滚动查看全部 30 轮
- **优先级**：P0（MVP，立项书成功标准 1）
- **涉及页面**：不涉及（数据层逻辑，界面表现归 REQ-001/004）

### REQ-003 新建会话

- **用户故事**：作为用户，我要一键新建一个空白会话，以便开始一个与之前话题无关的新对话。
- **描述**：提供"新建会话"入口，创建空会话并切换为当前会话。
- **主流程**：
  1. 用户点击"新建会话"
  2. 系统创建空会话（自动命名，见 REQ-009），切换到空白对话界面
  3. 新会话出现在会话列表顶部
- **异常分支**：
  - 当前会话回复正在生成中：**中断生成**（CEO 已拍板），原会话中该回复保留已生成部分并标注"生成中断"，不后台继续
- **验收标准**：
  - 点击"新建会话"后 300ms 内界面切换为空白对话界面，输入框可输入
  - 新会话在会话列表可见，刷新页面后仍存在（依赖 REQ-006）
  - 连续新建 10 个会话，列表完整显示 10 条，无重复 ID
  - 生成中点击新建：原会话的回复停止增长且标注"生成中断"，新会话界面立即可输入
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）

### REQ-004 查看历史会话并切换

- **用户故事**：作为用户，我要看到我的历史会话列表并点击任一会话恢复查看，以便回顾和继续之前的对话。
- **描述**：侧边（或顶部）会话列表展示全部历史会话，点击切换到该会话并完整展示其消息。生成中切换会话**不中断**：原会话在后台继续流式生成，完成后切回可见完整回复（CHG-001，2026-08-15 修改；原"中断并标注"仅保留给"生成中新建会话"场景，见 REQ-003）。
- **主流程**：
  1. 用户打开应用，会话列表按最近活跃时间倒序展示
  2. 点击任一会话
  3. 消息区加载该会话全部消息并定位到最新一条
- **异常分支**：
  - 无任何历史会话：显示空状态引导（如"点击新建会话开始对话"），不显示空白列表
  - 会话数据损坏 / 读取失败：该会话在列表中标注"无法读取"，不影响其他会话的展示与使用
  - 切换时原会话正在生成：不中断，原会话后台继续生成（CHG-001）；切回时可看到已生成的部分或完整回复
- **验收标准**：
  - 含 50 个会话、每会话 20 轮消息时，点击会话到消息完整渲染 < 1 秒，滚动到最新消息
  - 空态：无会话时显示引导文案，不出现 JS 报错
  - 切换会话后再切回，消息内容与切换前一致
- **优先级**：P0（MVP，立项书成功标准 2）
- **涉及页面**：design/iter-1（已基线）

### REQ-005 删除会话

- **用户故事**：作为用户，我要删除不需要的会话，以便保持会话列表整洁。
- **描述**：会话列表项提供删除操作，需二次确认以防误删。
- **主流程**：
  1. 用户在某会话上触发删除
  2. 弹出确认提示
  3. 确认后该会话从列表和本地存储中移除
  4. 若删除的是当前会话，自动切换到列表中最近的会话；若已无会话，显示空态
- **异常分支**：
  - 取消确认：会话保留，无任何变化
  - 删除后本地存储写入失败：界面提示删除失败，会话保留
- **验收标准**：
  - 删除必须经确认，未确认前会话不被移除
  - 删除后刷新页面，该会话不再出现（本地存储中确实清除）
  - 删除当前会话后界面不出现空白或报错，按上述规则切换
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）

### REQ-006 会话持久化与恢复（服务端存储）

- **用户故事**：作为用户，我要我的会话在关闭应用后依然保存，以便下次打开继续，不丢任何内容。
- **描述**（CHG-004 改写；CHG-004 已批准（2026-08-15，req-baseline-v3））：会话（含消息、branches 分支）的**唯一持久层为服务端数据库**，读写经 REQ-022 的云存储与同步承载。浏览器 IndexedDB **不再作为运行时存储**，仅保留一次性角色：**v0.4.0 及以前旧版本本地数据的迁移数据源**，配合「导入本地会话到云端」入口（REQ-022）使用；导入完成后本地数据保留只读 30 天再自动清除。**必须登录后才能使用**：未登录只能看到登录页（REQ-020），本地不再产生新的会话数据。
- **主流程**：
  1. 用户登录（REQ-020），前端从服务端加载会话列表与数据
  2. 每轮对话完成后写回服务端（REQ-022）
  3. 关闭浏览器/换设备重新登录，会话列表与消息完整恢复
- **异常分支**：
  - 服务端写入失败：按 REQ-022 异常分支处理（本地暂存重试，不静默丢数据）
  - 服务端读取失败：提示并可重试，不显示空白假象
  - 本地遗留旧版本数据未导入：首次登录后提供迁移入口（REQ-022），不导入不影响云端新数据的使用
- **验收标准**：
  - 完成一轮对话后关闭标签页，重新登录打开：该会话与消息内容逐字保留
  - 流式生成中途刷新页面：已完成的轮次保留，未完成的 AI 回复标注「生成中断」且不出现半条损坏消息
  - 未登录状态访问任何功能页：一律跳转登录页，且本地 IndexedDB 不产生新的会话数据写入
  - 旧版本本地 20 个会话经迁移入口导入后，云端会话数一致；导入后本地数据转为只读，30 天后被清除（可观测）
- **优先级**：P0（原 IndexedDB 单机方案由变更记录 CHG-004 存档）
- **涉及页面**：不涉及（数据层；迁移入口见 REQ-022）

### REQ-007 调用异常与降级提示

- **用户故事**：作为用户，我要在 AI 服务出错时得到人话的提示和可行的下一步，以便知道是等待、重试还是检查配置。
- **描述**：对第三方 API 的常见错误（网络失败、超时、401 密钥无效、429 限流、5xx 服务异常）给出区分化的提示文案与建议动作。
- **主流程**：
  1. 请求失败时，按错误类型映射为用户可读的提示（如"服务暂时不可用，请稍后重试"）
  2. 可重试的错误（网络/超时/5xx/429）提供"重试"按钮，重试复用原消息
- **异常分支**：
  - 401/403（密钥无效/无权限）：提示"API 密钥无效，请检查设置"，并提供**跳转到设置页（REQ-014）**更新密钥的入口
  - 429：提示稍后重试，不自动连发重试
  - 未配置 API 密钥即发送消息：不发出请求，提示并引导前往设置页
- **验收标准**：
  - 模拟网络断开、超时、429、401 四种错误，分别显示四种不同的提示文案，无技术性报错堆栈直接暴露给用户
  - 401 提示中包含可点击的设置页入口，点击后打开设置页（REQ-014）
  - 每种可重试错误的"重试"点击后重新发起请求，成功后正常流式显示
  - 错误提示在 3 秒内出现（不含网络层自身的超时等待）
- **优先级**：P0（MVP，立项书约束"需考虑降级与错误提示"）
- **涉及页面**：design/iter-1（已基线）

### REQ-008 系统提示词设置

- **用户故事**：作为用户，我要为会话设置系统提示词（如"你是一个简洁的翻译助手"），以便定制 AI 的角色与风格。
- **描述**：提供设置入口，可编辑系统提示词；系统提示词作为上下文第一条随每次请求发送（参与 REQ-002 的上下文组装，不受 20 轮截断影响）。**优先级 CEO 已拍板为 P1，不进 MVP。**
- **主流程**：
  1. 用户打开设置，输入系统提示词并保存
  2. 后续请求将该提示词置于上下文首位
  3. AI 按该角色设定回复
- **异常分支**：
  - 留空：按无系统提示词正常请求，不报错
  - 修改已有会话的系统提示词：只影响之后的轮次，历史消息不变
- **验收标准**：
  - 设置"回复只用英文"后，同一会话内 AI 回复为英文；清除设置后恢复默认行为
  - 系统提示词随会话持久化，刷新后仍生效
  - 会话超过 20 轮时，请求体中系统提示词仍在首位（不被截断）
- **优先级**：P1（CEO 已确认）
- **涉及页面**：design/iter-2（已基线）

### REQ-009 会话自动命名

- **用户故事**：作为用户，我要每个会话有可辨认的标题，以便在列表中快速找到目标会话。
- **描述**：新会话默认以时间或首条用户消息摘要命名；可自动（用首条消息前 N 字）实现，无需额外调用 AI。
- **主流程**：
  1. 新建会话，标题初始为"新会话"或时间戳
  2. 用户发出第一条消息后，标题更新为该消息前 20 字（截断加省略号）
- **异常分支**：
  - 首条消息为空：不更新标题（发送已被 REQ-001 拦截，不会发生）
- **验收标准**：
  - 发送"帮我写一封请假邮件，理由是家里有事"后，列表中该会话标题为其前 20 字
  - 同一用户并发多会话时，标题与内容对应正确
- **优先级**：P1
- **涉及页面**：design/iter-3（已基线）

### REQ-010 停止生成

- **用户故事**：作为用户，我要在 AI 回复过程中随时点击"停止"，以便中断无用或过长的回答并立即继续提问。
- **描述**：流式生成中，发送按钮切换为"停止"；点击后终止流，保留已生成部分。
- **主流程**：
  1. 流式生成中用户点击"停止"
  2. 流被终止，已生成内容保留并标注完成
  3. 输入框恢复可用
- **异常分支**：
  - 停止请求发出时流已恰好结束：按正常结束处理，不报错
- **验收标准**：
  - 点击停止后 200ms 内停止渲染新内容，输入框可再次发送
  - 已生成部分保留且随会话持久化
- **优先级**：P1
- **涉及页面**：design/iter-2（已基线）

### REQ-011 Markdown 渲染与代码块复制

- **用户故事**：作为用户，我要 AI 回复中的列表、表格、代码块正确渲染，并能一键复制代码，以便直接使用回答内容。
- **描述**：AI 回复按 Markdown 渲染；代码块带语言标签和复制按钮。
- **主流程**：
  1. AI 回复含 Markdown 语法
  2. 渲染为对应富文本；代码块右上角显示"复制"按钮
  3. 点击复制后按钮短暂变为"已复制"
- **异常分支**：
  - 回复为纯文本：按普通段落渲染，不出错
- **验收标准**：
  - 含标题/列表/表格/代码块的回复渲染后结构与语法对应
  - 点击复制后，系统剪贴板内容与代码块原文逐字一致
- **优先级**：P1
- **涉及页面**：design/iter-3（已基线）

### REQ-013 导出会话

- **用户故事**：作为用户，我要把某个会话导出为 Markdown/文本文件，以便备份或分享。
- **验收标准**：
  - 导出文件包含该会话全部消息（区分用户/AI），文件可被普通文本编辑器打开
- **优先级**：P2

  - 编辑后刷新页面，编辑结果持久化
  - 生成中编辑历史消息并确认：原回复停止增长并标注「生成中断」，从编辑点起出现新回复

  - 登录时用户名或密码错误：统一提示「用户名或密码错误」，不区分具体是哪项错、不泄露账号是否存在

  - 数据库中检索不到任何密码明文（密码字段均为哈希值）
  - 密码错误登录：3 秒内出现统一错误提示
  - 手动使 token 失效后发送消息：收到 401 并跳转登录页
- **优先级**：P0（CEO 已确认）
- **涉及页面**：design/iter-6（已基线，2026-08-15 CEO 批准；登录/注册原型承载，NCR-iter6-006 补记见 changes.md CHG-004 澄清定案 9）

### REQ-022 服务端会话云存储与多设备同步〔CHG-004〕

- **用户故事**：作为用户，我要我的会话保存在服务端并在所有登录设备上保持一致，以便换设备继续对话且数据不丢失。
- **描述**（CHG-004 已批准（2026-08-15，req-baseline-v3））：登录用户的会话（含消息、branches 分支、系统提示词、供应商档案）存储于后端数据库，为唯一持久层（承接 REQ-006）；前端打开时从服务端加载，每轮对话完成/变更后写回。多设备并发修改同一会话的冲突策略为**最后写入覆盖（LWW，CEO 已拍板）**：被覆盖端下次加载以后端数据为准，不弹冲突解决 UI。提供**一次性「导入本地会话到云端」迁移入口**（面向 v0.4.0 及以前的本地数据）：导入后本地数据保留只读 30 天再自动清除。**不保留未登录本地模式（必须登录）**。
- **主流程**：
  1. 用户登录成功，前端从服务端拉取其会话列表与数据
  2. 对话、重命名、删除、编辑、版本切换等操作同步写入服务端（对应 REQ-001~019 的既有交互，仅数据读写层换源）

  - 多设备并发修改同一会话：按 LWW 覆盖，不报错、不弹冲突 UI
  - 会话数量/体量大：列表分页或增量加载（阈值由性能测试定）
  - 迁移导入：过程可取消；本地会话作为**新增**导入，不覆盖云端已有会话
- **验收标准**：
  - 设备 A 完成一轮对话后，设备 B 登录并刷新，5 秒内可见该会话且内容逐字一致
  - 设备 A 删除会话，设备 B 刷新后该会话消失
  - 断网状态下完成的一轮对话，恢复网络后自动同步到服务端，另一设备可见
  - 两设备同时修改同一会话标题：后保存者生效，另一端刷新后与后端一致（LWW）
  - 旧版本本地 10 个会话经迁移入口导入后，云端会话数与内容一致；导入后本地数据只读、30 天后被清除（可观测）
- **优先级**：P0（CEO 已确认）
- **涉及页面**：迁移入口 design-iter-8（已基线，2026-08-16——提示条/导入中可取消/完成只读 30 天说明/失败重试）

### REQ-023 API 密钥服务端代管与 OpenAI 兼容流式代理〔CHG-004〕

- **用户故事**：作为用户，我要零配置直接对话（服务端统一密钥），也可自备密钥获得更高配额，且密钥全程由服务端安全代管，以便使用门槛低且密钥不暴露在浏览器。
- **描述**（CHG-004 已批准（2026-08-15，req-baseline-v3））：后端提供 OpenAI 兼容的流式对话代理：前端将对话请求发往后端，后端完成用户鉴权（REQ-020）与配额检查（REQ-024）后，按当前生效供应商档案（REQ-018）转发至上游（DeepSeek/GLM 等），并以流式（SSE）回传前端。**密钥双模式（CEO 已拍板）**：默认服务端统一 key（免费档配额内使用）；用户自填 key 存服务端并解锁更高档配额（配置入口见 REQ-014 高级设置）。API 密钥仅存服务端，绝不下发前端。
- **主流程**：
  1. 前端按 REQ-002 规则组装上下文，发送至后端代理端点
  2. 后端校验会话 token 与配额（按该用户当前密钥模式的配额档位）
  3. 按生效档案转发上游 chat completions（stream）——统一 key 模式用服务端密钥，自填模式用该用户档案密钥
  4. 上游流式块经后端实时转发，前端按 REQ-001 渲染
- **异常分支**：
  - token 无效/过期：返回 401，前端跳登录页（REQ-020）
  - 配额不足：返回配额提示（REQ-024），不调用上游
  - 上游 401/403/429/5xx/超时：错误类型透传或映射，前端按 REQ-007 提示并提供重试
  - 上游连接中断：前端标注「生成中断」，已收内容保留（与 REQ-001 一致）
- **验收标准**：
  - 浏览器网络面板的全部请求中检索不到任何 API key 明文
  - 统一 key 模式：新注册用户零配置完成一次流式对话；自填 key 模式：DeepSeek 与 GLM 各完成一次经代理的流式对话
  - 代理转发引入的流式首块额外延迟 ≤ 500ms（与直连同环境对比）
  - 配额不足的请求不抵达上游（服务端日志可验证）
  - 服务端存储中的密钥为受保护存储；git 仓库（前端与后端）全量历史检索不到任何真实 key（沿用既有验证方式）
- **优先级**：P0（CEO 已确认）
- **涉及页面**：design/iter-7（已基线，2026-08-16 CEO 批准——高级设置双模式 + 错误透传映射）

### REQ-024 用量配额与滥用防护〔CHG-004〕

- **用户故事**：作为服务部署者，我要对注册与调用设置频率与配额限制，以便服务公开注册后不被滥用、API 密钥消耗可控。
- **描述**（CHG-004 已批准（2026-08-15，req-baseline-v3））：公开注册（REQ-020）的必要防护，含：注册频率限制（按 IP）、每用户调用配额（按请求数或 token 数、按周期重置）、服务端统一 key 的总量保护（每日上限/熔断）。**配额分档与密钥模式联动**：统一 key 模式 = 免费档配额；自填 key 模式 = 更高档配额（REQ-023）。配额数值为可配置参数，由管理员经 Web 后台按用户调整（REQ-025），初始默认值已于 iter-8 计划定案（2026-08-16 CEO 拍板：免费档 30 / 自填档 500 / 统一 key 总量 2000，每自然日对话请求数；注册限频每 IP 每日 3——CHG-004「后续待定」销账）
- **主流程**：
  1. 用户正常使用，配额充足时无感知
  2. 后端逐次检查配额并计数
  3. 重置周期到达后配额恢复
- **异常分支**：
  - 同 IP 注册超过阈值（默认每 IP 每天 3 个，管理员可调）：拒绝注册并明确提示
  - 用户调用超当前档位配额：返回「配额已用尽，重置时间 XX」，不再调用上游；统一 key 模式下提示可通过高级设置自填 key 解锁更高配额
  - 服务端总消耗达每日上限（统一 key 模式）：全站暂停新对话请求并提示，次日恢复
- **验收标准**：
  - 同 IP 连续注册超过阈值后，下一次注册被拒且提示明确
  - 将测试账号配额设为 5 次：第 6 次发送消息收到配额提示，服务端日志显示该请求未转发上游
  - 周期重置后同一账号可再次调用
  - 统一 key 每日上限触发后，所有账号的对话请求均收到暂停提示
  - 管理员经 REQ-025 后台调整某用户配额后，该用户实际可用量按新值生效
- **优先级**：P0（CEO 已确认——公开注册前提下，滥用防护与用量控制是上线必要条件）
- **涉及页面**：不涉及（提示复用现有错误提示体系；管理操作见 REQ-025）

### REQ-025 管理员 Web 后台〔CHG-004〕

- **用户故事**：作为服务部署者（管理员），我要通过 Web 后台封禁/解封用户、按用户调整配额、查看用量统计，以便公开注册后可治理滥用并掌握服务消耗。
- **描述**（CHG-004 已批准（2026-08-15，req-baseline-v3））：**首个注册用户自动成为管理员**。管理员登录后可进入 Web 管理后台，提供三类能力：① 用户治理（封禁/解封，被封禁用户无法登录与调用）；② 配额管理（按用户调整配额档位/数值，覆盖默认值，联动 REQ-024）；③ 用量统计——最小可行口径：**按用户按日的请求数与 token 数列表**（支持过滤与排序即可，图表不做）。普通用户不可见后台入口与任何后台数据。与暂缓池「用量与费用统计面板」的边界：该条为面向普通用户的个人用量面板，本条为管理员治理后台。
- **主流程**：
  1. 首个用户注册，系统标记为管理员
  2. 管理员登录，进入后台，看到用户列表（注册时间、状态、配额档位、近期用量）
  3. 对滥用用户执行封禁；对可信用户上调配额
  4. 查看按用户按日的请求数与 token 数列表
- **异常分支**：
  - 管理员尝试封禁自己：系统阻止并提示（不允许封禁管理员本人）
  - 被封禁用户尝试登录/调用：明确提示「账号已被封禁」，无法使用
  - 非管理员访问后台路由/接口：返回 403，不暴露任何后台数据
  - 用量数据缺失（统计中断）：显示已有数据并标注缺失时段，不编造（呼应铁律 5：度量数据只允许机器采集）
- **验收标准**：
  - 首个注册用户具有管理员标识；第二个注册用户为普通用户，其访问后台路由返回 403
  - 封禁某用户后：该用户登录被拒并看到封禁提示；解封后可正常登录使用
  - 管理员将某用户配额由默认调整为 N 后，该用户实际可用量按 N 生效（与 REQ-024 验收联动）
  - 后台可见按用户按日的请求数与 token 数列表，与后端调用日志计数一致（抽样比对 3 天数据一致）
  - 普通用户的任何界面/接口均获取不到其他用户的用量数据
- **优先级**：P1（CEO 已确认）
- **涉及页面**：design/iter-8（已基线，2026-08-16 CEO 批准——管理后台原型：用户列表/封禁/调配额/用量列表/403 门禁/全站配额条；四项定夺按推荐定案）
