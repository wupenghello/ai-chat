## 1. 产品概述

ai-chat 为多个用户提供 AI 对话服务：任何人可注册账号使用，对话经自建后端统一接入第三方大模型 API（OpenAI 兼容协议，DeepSeek/GLM），支持流式输出的多轮连贯对话；会话数据存储在服务端，同一账号多设备数据一致。产品定位为**多用户自部署 Web 服务**——单人即可部署、供多人注册使用的自托管服务。产品形态为**多用户自部署的 AI agent 对话服务**：除纯文本对话外，AI 可经服务端工具网关调用工具（首个生产工具为联网搜索，随 A2 交付），并将工具步骤与来源引用呈现给用户；上下文组装、回合编排与配额计量由服务端 agent 运行时承担（CHG-007，2026-08-17 方向升级）。RAG/知识库仍暂缓（见想法池）。

**架构决策（2026-08-15 CEO 拍板；CHG-004 已批准（2026-08-15，req-baseline-v3））**：应用为**前后端分离架构**——前端 Vue3 + TS + Vite 不变；新增 **Python FastAPI 后端**，职责：① 用户账号体系（注册/登录/会话管理，用户名+密码自管，不依赖第三方登录；**不保留未登录本地模式，必须登录**）；② API 密钥统一管理与服务端代管，**双模式**——默认服务端统一 key（配额内免费额度），高级设置允许用户自填 key 存服务端并解锁更高配额；③ OpenAI 兼容流式请求的代理转发；④ 用户数据（会话/供应商档案）云端存储；⑤ **agent 运行时**（CHG-007，2026-08-17）：ReAct 循环（最大步数/单步超时/断连取消三护栏）、工具网关（注册/参数校验/出网固定域白名单/超时/结果大小限制/注入防护）、SSE 事件协议 v2（服务端解析重组、独立回合端点，事件表见 changes.md CHG-007 内容 4.1）、上下文组装迁服务端（规则照搬：系统提示词 + 最近 20 轮）、配额按回合计——技术口径全文见 changes.md CHG-007。公开注册前提下，滥用防护与用量配额为上线必要条件（REQ-024，P0）；服务治理由 Web 管理后台承担（REQ-025，P1）。

**仓库布局（2026-08-15 CEO 拍板，CHG-004 实施层细化）**：同仓库 monorepo——后端代码置于本仓库新增 `backend/` 目录（Python/FastAPI，独立依赖文件与 lockfile，.gitignore 排除 `__pycache__`/`.venv`）；前端代码保持根目录现状不动；`docker-compose.yml` 放仓库根目录统一编排。不另建独立后端仓库、不用 submodule。

> 决策历史：2026-08-15（req-baseline-v1）曾拍板「纯前端应用直连第三方 API，不自建后端」；同日 CEO 决策升级为自建 FastAPI 后端（CHG-004），原决策由上文替换，原文存于变更历史（changes.md / git 历史）。2026-08-15 CHG-004 决策「联网搜索本轮不做」；2026-08-17 CEO 方向决策升级为 agent 架构，联网搜索作为第一个生产工具纳入（CHG-007），原文存变更历史与 docs/architecture-upgrade-plan-2026-08-17.md。

## 2. 用户故事

### REQ-001 发送消息并流式接收回复（CHG-007 改写：回合事件流）

- **用户故事**：作为用户，我要在输入框输入文本并发送，以便获得 AI 的回答，且回答以流式方式逐步显示，以便我不必等待完整生成。
- **描述**：对话主界面的核心交互：文本输入框 + 发送按钮 + 消息展示区。AI 回复以打字机效果流式渲染。
- **主流程**：
  1. 用户在输入框输入文本（支持多行）
  2. 点击发送按钮或按回车（Shift+Enter 换行）
  3. 用户消息立即显示在消息区，输入框清空
  4. AI 回复以**回合（turn）**为单位流式渲染：文本增量逐步显示（打字机效果不变）；模型调用工具时，消息流内出现工具步骤（运行中/完成/失败状态、可折叠、结果卡，REQ-032），工具结果返回后回答继续流式生成（CHG-007，基线 req-baseline-v5）
  5. 回合结束后，回复气泡标记为完成
- **异常分支**：
  - 输入为空或仅含空白字符：发送按钮不可用，点击无动作，不发出请求
  - 发送时上一条回复仍在生成中：禁用发送（或提示等待），不并发请求
  - 网络失败 / API 报错 / 超时：该 AI 气泡显示明确错误提示（含错误类型），并提供"重试"入口；用户已发出的消息保留在消息区，不丢失
  - 流式中断：已收到的部分内容保留显示，并标注"生成中断"
  - 工具步骤失败 / 单步超时：工具步骤卡标「失败/超时」，模型收到错误结果可降级直答，回合继续不崩（口径见 REQ-030 异常分支，CHG-007）
  - 回合被步数上限截停：回复末尾标注「已到单回合步数上限」，已生成内容保留（REQ-030）
  - 断连取消：服务端取消上游调用与工具执行，未完成回复标注「生成中断」（REQ-030）
- **验收标准**：
  - 输入"你好"并发送后，1 秒内用户消息出现在消息区
  - 收到首个流式数据块后 200ms 内，回复气泡开始显示内容
  - 回复过程中界面无需整体刷新，历史消息不重排闪烁
  - 发送空字符串 / 纯空格：无请求发出，无新气泡产生
  - 断网状态下发送：3 秒内出现含错误提示的气泡，且提供重试；重试成功后正常流式显示
  - 回合事件序逐帧断言见 REQ-030 验收 1（CHG-007 归位）；本条既有验收零回退
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）

### REQ-002 多轮上下文记忆（CHG-007 改写：组装迁服务端）

- **用户故事**：作为用户，我要 AI 记住我在本会话中说过的话，以便进行多轮连贯对话而不必每次重复背景。
- **描述**（CHG-007 改写，基线 req-baseline-v5）：上下文组装由**服务端 agent 运行时**执行（REQ-033，前端不再组装与上传历史）：服务端按会话存储的消息取**系统提示词（如有，见 REQ-008）+ 最近 20 轮（最多 40 条消息）**组装；回合内工具结果注入当轮上下文、不占 20 轮窗口。20 轮窗口为现状规则照搬，终态演进为多级压缩（B2，见暂缓池）。
- **主流程**：
  1. 用户发送第 N 条消息
  2. 服务端按上述规则组装请求上下文（前端仅上送本条消息，REQ-033）
  3. AI 回复与上文指代、事实保持连贯
- **异常分支**：
  - 会话消息超出 20 轮：自动截断，仅携带最近 20 轮，不报错、不中断对话；被截断轮次仍完整保留在本地与界面中
- **验收标准**：
  - 连续对话测试：第 1 轮告知"我叫小明"，第 5 轮问"我叫什么"，AI 回答包含"小明"
  - 第 10 轮对话的请求中可观测到包含此前轮次的消息（服务端 pytest 断言，MockTransport 捕获上游请求体——CHG-007 服务端化口径）
  - 第 30 轮对话的请求体中仅包含最近 20 轮消息（服务端 pytest 断言），对话仍正常进行，无报错；界面仍可滚动查看全部 30 轮
- **优先级**：P0（MVP，立项书成功标准 1）
- **涉及页面**：不涉及（数据层逻辑，界面表现归 REQ-001/004）

### REQ-003 新建会话

- **用户故事**：作为用户，我要一键新建一个空白会话，以便开始一个与之前话题无关的新对话。
- **描述**：提供"新建会话"入口，创建空会话并切换为当前会话。
- **主流程**：
  1. 用户点击"新建会话"
  2. 系统创建空会话（自动命名，见 REQ-009），切换到空白对话界面
  3. 新会话出现在会话列表顶部
- **异常分支**：
  - 当前会话回复正在生成中：**中断生成**（CEO 已拍板），原会话中该回复保留已生成部分并标注"生成中断"，不后台继续
- **验收标准**：
  - 点击"新建会话"后 300ms 内界面切换为空白对话界面，输入框可输入
  - 新会话在会话列表可见，刷新页面后仍存在（依赖 REQ-006）
  - 连续新建 10 个会话，列表完整显示 10 条，无重复 ID
  - 生成中点击新建：原会话的回复停止增长且标注"生成中断"，新会话界面立即可输入
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）+ design-iter-11（已基线，2026-08-16——新建钮随侧栏改版，点击清空搜索口径）

### REQ-004 查看历史会话并切换

- **用户故事**：作为用户，我要看到我的历史会话列表并点击任一会话恢复查看，以便回顾和继续之前的对话。
- **描述**：侧边（或顶部）会话列表展示全部历史会话，点击切换到该会话并完整展示其消息。生成中切换会话**不中断**：原会话在后台继续流式生成，完成后切回可见完整回复（CHG-001，2026-08-15 修改；原"中断并标注"仅保留给"生成中新建会话"场景，见 REQ-003）。
- **主流程**：
  1. 用户打开应用，会话列表按最近活跃时间倒序展示
  2. 点击任一会话
  3. 消息区加载该会话全部消息并定位到最新一条
- **异常分支**：
  - 无任何历史会话：显示空状态引导（如"点击新建会话开始对话"），不显示空白列表
  - 会话数据损坏 / 读取失败：该会话在列表中标注"无法读取"，不影响其他会话的展示与使用
  - 切换时原会话正在生成：不中断，原会话后台继续生成（CHG-001）；切回时可看到已生成的部分或完整回复
- **验收标准**：
  - 含 50 个会话、每会话 20 轮消息时，点击会话到消息完整渲染 < 1 秒，滚动到最新消息
  - 空态：无会话时显示引导文案，不出现 JS 报错
  - 切换会话后再切回，消息内容与切换前一致
- **优先级**：P0（MVP，立项书成功标准 2）
- **涉及页面**：design/iter-1（已基线）+ design-iter-11（已基线，2026-08-16——列表项单行化/时间分组载体）

### REQ-005 删除会话

- **用户故事**：作为用户，我要删除不需要的会话，以便保持会话列表整洁。
- **描述**：会话列表项提供删除操作，需二次确认以防误删。
- **主流程**：
  1. 用户在某会话上触发删除
  2. 弹出确认提示
  3. 确认后该会话从列表和本地存储中移除
  4. 若删除的是当前会话，自动切换到列表中最近的会话；若已无会话，显示空态
- **异常分支**：
  - 取消确认：会话保留，无任何变化
  - 删除后本地存储写入失败：界面提示删除失败，会话保留
- **验收标准**：
  - 删除必须经确认，未确认前会话不被移除
  - 删除后刷新页面，该会话不再出现（本地存储中确实清除）
  - 删除当前会话后界面不出现空白或报错，按上述规则切换
- **优先级**：P0（MVP）
- **涉及页面**：design/iter-1（已基线）+ design-iter-11（已基线，2026-08-16——删除入口迁列表项「···」菜单）

### REQ-006 会话持久化与恢复（服务端存储；CHG-007 改写：v2 blocks）

- **用户故事**：作为用户，我要我的会话在关闭应用后依然保存，以便下次打开继续，不丢任何内容。
- **描述**（CHG-004 改写；CHG-004 已批准（2026-08-15，req-baseline-v3））：会话（含消息、branches 分支）的**唯一持久层为服务端数据库**；消息模型升级为 v2 blocks（CHG-007/REQ-032，基线 req-baseline-v5）——**新格式写档带会话 JSON 顶层 `schema: 2` 标记，存量 string 会话不迁移、读时归一化**；读写经 REQ-022 的云存储与同步承载（含跨格式写侧守卫）。浏览器 IndexedDB **不再作为运行时存储**，仅保留一次性角色：**v0.4.0 及以前旧版本本地数据的迁移数据源**，配合「导入本地会话到云端」入口（REQ-022）使用；导入完成后本地数据保留只读 30 天再自动清除。**必须登录后才能使用**：未登录只能看到登录页（REQ-020），本地不再产生新的会话数据。
- **主流程**：
  1. 用户登录（REQ-020），前端从服务端加载会话列表与数据
  2. 每轮对话完成后写回服务端（REQ-022）
  3. 关闭浏览器/换设备重新登录，会话列表与消息完整恢复
- **异常分支**：
  - 服务端写入失败：按 REQ-022 异常分支处理（本地暂存重试，不静默丢数据）
  - 服务端读取失败：提示并可重试，不显示空白假象
  - 本地遗留旧版本数据未导入：首次登录后提供迁移入口（REQ-022），不导入不影响云端新数据的使用
- **验收标准**：
  - 完成一轮对话后关闭标签页，重新登录打开：该会话与消息内容逐字保留
  - 流式生成中途刷新页面：已完成的轮次保留，未完成的 AI 回复标注「生成中断」且不出现半条损坏消息
  - 未登录状态访问任何功能页：一律跳转登录页，且本地 IndexedDB 不产生新的会话数据写入
  - 旧版本本地 20 个会话经迁移入口导入后，云端会话数一致；导入后本地数据转为只读，30 天后被清除（可观测）
  - 老 string 会话（含 branches）在新前端渲染逐字零回退（= REQ-032 验收 1，CHG-007）
- **优先级**：P0（原 IndexedDB 单机方案由变更记录 CHG-004 存档）
- **涉及页面**：不涉及（数据层；迁移入口见 REQ-022）

### REQ-007 调用异常与降级提示

- **用户故事**：作为用户，我要在 AI 服务出错时得到人话的提示和可行的下一步，以便知道是等待、重试还是检查配置。
- **描述**：对第三方 API 的常见错误（网络失败、超时、401 密钥无效、429 限流、5xx 服务异常）给出区分化的提示文案与建议动作。
- **主流程**：
  1. 请求失败时，按错误类型映射为用户可读的提示（如"服务暂时不可用，请稍后重试"）
  2. 可重试的错误（网络/超时/5xx/429）提供"重试"按钮，重试复用原消息
- **异常分支**：
  - 401/403（密钥无效/无权限）：提示"API 密钥无效，请检查设置"，并提供**「前往高级设置」入口——打开设置弹窗并直达高级设置分区（REQ-028/014）**
  - 429：提示稍后重试，不自动连发重试
  - 自填 key 校验失败（上游 401/403 经代理映射）：错误气泡只显「前往高级设置」不显重试（v3 起统一 key 零配置，「未配置即发送」分支消亡，design-iter-7 §3.1）
- **验收标准**：
  - 模拟网络断开、超时、429、401 四种错误，分别显示四种不同的提示文案，无技术性报错堆栈直接暴露给用户
  - 401 提示中包含可点击的「前往高级设置」入口，点击后打开设置弹窗并直达高级设置分区（REQ-028/014）
  - 每种可重试错误的"重试"点击后重新发起请求，成功后正常流式显示
  - 错误提示在 3 秒内出现（不含网络层自身的超时等待）
- **优先级**：P0（MVP，立项书约束"需考虑降级与错误提示"）
- **涉及页面**：design/iter-1（已基线）+ design/iter-7（错误映射定稿）+ design-iter-11（已基线，2026-08-16——「前往高级设置」打开设置弹窗直达高级设置分区，REQ-028）

### REQ-008 系统提示词设置

- **用户故事**：作为用户，我要为会话设置系统提示词（如"你是一个简洁的翻译助手"），以便定制 AI 的角色与风格。
- **描述**：提供设置入口，可编辑系统提示词；系统提示词作为上下文第一条随每次请求发送（参与 REQ-002 的上下文组装，不受 20 轮截断影响；CHG-007 起由服务端组装器置于上下文首位，规则不变）。**优先级 CEO 已拍板为 P1，不进 MVP。**
- **主流程**：
  1. 用户打开设置，输入系统提示词并保存
  2. 后续请求将该提示词置于上下文首位
  3. AI 按该角色设定回复
- **异常分支**：

### REQ-022 服务端会话云存储与多设备同步〔CHG-004；CHG-007 守卫〕

  3. 另一设备登录同一账号，刷新后看到相同会话列表与内容
- **异常分支**：
  - 拉取会话失败（网络/服务异常）：提示并可重试，不显示空白假象

  - 多设备新旧客户端并存（升级窗口期）：旧格式载荷覆盖新格式存量 → 409 拒绝（见上守卫）；新格式覆盖旧格式 → 正常保存（升级）；同格式并发 → LWW 照旧（CHG-007）
  - 会话数量/体量大：列表分页或增量加载（阈值由性能测试定）

  - 断网状态下完成的一轮对话，恢复网络后自动同步到服务端，另一设备可见
  - 两设备同时修改同一会话标题：后保存者生效，另一端刷新后与后端一致（LWW）
  - 旧版本本地 10 个会话经迁移入口导入后，云端会话数与内容一致；导入后本地数据只读、30 天后被清除（可观测）
  - LWW 守卫（CHG-007）：① v2 存量 + 无标记 v1 载荷 → 409 且 GET 复读存量逐字不变（pytest）；② 带标记整档透传回写（模拟老客户端 GET v2 后改名回写）→ 200 保存、blocks 与标记保留（pytest）

### REQ-030 工具调用框架与 ReAct 循环（含内置演示工具）〔CHG-007〕

- **用户故事**：作为用户，我要 AI 在需要时调用工具完成纯文本模型做不到的事（查实时信息、执行可验证操作），并让我看到它每一步在做什么，以便信任并核验回答的来源与过程。

- **主流程**：
  1. 前端将**仅本条用户消息** + 会话 id POST 至回合端点（独立端点 `/api/chat/turn`，design-iter-13 定夺；历史不上传，见 REQ-033）
  2. 后端校验会话 token → 按回合计检查配额（REQ-034；不足即 429，零上游调用）→ 创建回合（turn_id）并下发 `turn.start`
  3. 服务端自库取会话消息 → 归一化（v1/v2 统一展开）→ 组装上下文（系统提示词 + 最近 20 轮）+ 注册表工具定义 → 首次上游流式调用

  5. 工具结果以 tool role 消息回填本轮上下文 → 步数 +1（下发 `turn.step`）→ 未到步数上限且模型仍要求调用工具 → 回到 4；模型给出最终回答或到上限 → 定型
  6. 回合结束：下发 `usage`（回合内 tokens 累计）→ `turn.end`（reason=done/max_steps/aborted/error）；assistant 消息以 blocks 落库（REQ-032），usage 落 usage_daily（REQ-034）
- **异常分支（逐项，含用户所见）**：
  - 入参异常（空文本/超长）：422 拒绝；前端本就禁发空输入（REQ-001），双保险
  - 上游报错（401/403/429/5xx/超时）：沿 REQ-007 既有映射——错误气泡（含类型与建议动作）+ 可重试错误提供重试；本回合已生成的文本与工具步骤保留
  - 上游连接中断：沿用既有 `upstream_interrupted` 自定义帧 → 已收内容保留、标注「生成中断」
  - 工具执行报错/超时：`tool.result` 带 error/timeout → 工具步骤卡标「失败/超时」；错误结果回填模型，模型可降级直答（回合继续，不崩）；连续工具失败无独立熔断（由步数上限兜底）
  - 步数到顶：回合终止（turn.end reason=max_steps）→ 回复末尾标注「已到单回合步数上限」（文案随 design-iter-13），已生成内容保留并落库
  - 断连取消：用户关闭页面/断网 → 服务端检测连接断开，取消进行中的上游调用与工具执行；已落库内容保留，未完成回复标注「生成中断」（与 REQ-006 刷新恢复口径衔接）；回合计费：已抵上游则计 1 回合、零上游调用的取消不计（design-iter-13 定夺）

  - 自填档案「支持工具」开关为关（CHG-007 定夺①）：本回合以无工具模式组装（tools 定义不下发），用户无感知差异
  - 演示工具未注册/被开关关闭：模型收到 error 结果，降级直答
- **验收标准（可判定；〔原表 N〕= CHG-007 验收条款归位编号）**：
  1. 〔原表 1〕2 步工具回合事件序逐帧断言（pytest + MockTransport）：帧序 = turn.start → turn.step(1) → text.delta* → tool.call → tool.result(ok) → turn.step(2) → text.delta* → usage → turn.end(done)，逐帧比对无乱序、无缺帧

  3. 〔原表 3〕单步超时：工具执行超过其声明超时（假工具 sleep 超限）→ tool.result(status=timeout)、无第二次执行，回合继续并降级直答

### REQ-031 工具网关安全基线〔CHG-007〕

- **用户故事**：作为服务部署者，我要所有工具调用经统一网关完成注册校验与出网管控，以便公开注册的服务不被工具层滥用（SSRF、超大结果、未审计调用）。
- **描述**（CHG-007 新增，基线 req-baseline-v5）：工具以服务端代码**静态注册**（A1 无动态/插件注册机制），每个工具声明：名称、入参 JSON Schema、是否出网、出网固定域白名单、单工具超时、结果大小上限（32 KiB，design-iter-13 定夺）。六项校验的逐项判定口径见 changes.md CHG-007 内容 4.5。不搬 BashTool 式 shell 检测（本产品不出 shell 工具；远期若加代码执行工具再立专项）。安全事件（拒绝/截断/超时）写服务端日志，机器采集，不含结果全文与密钥。出网治理随 A2 第一个真实出网工具（搜索）生效；A1 演示工具无出网。
- **主流程**：
  1. 运行时收到模型的 tool_call（name + arguments JSON 字符串）
  2. 网关依序执行：注册检查 → 参数校验（JSON Schema）→（出网工具）目标域名/IP 判定 → 执行（受单工具超时约束）→ 结果大小检查与截断 → 注入防护包裹
  3. 任一环节拒绝 → 直接产出 tool.result(status=error)（含机器可读原因），不执行后续环节；全部通过 → tool.result(status=ok)

- **验收标准（可判定）**：
  1. 〔原表 9-a〕未注册工具名 → error result 且工具体零执行（假传输层断言零调用）
  2. 〔原表 9-b〕出网仅白名单域：目标为内网/环回地址（127.0.0.1 / 10.x / 172.16~31.x / 192.168.x / 169.254.x / ::1）或非白名单域 → 连接不发起（假传输层零连接断言）；A1 演示工具无出网，A2 仅搜索域放行
  3. 〔原表 9-c〕超限截断：假工具返回 1 MiB → tool.result 结果长度 ≤ 上限且带截断标注
  4. 参数校验：入参缺字段/类型错 → error result 含校验原因，不执行
  5. 网关日志：每次调用记录工具名/状态/耗时/是否截断四字段，不含结果全文与密钥（pytest 断言日志结构）
- **优先级**：P0（CHG-007 建议，CEO 已批准）｜**批次**：A1（框架）/ A2（出网治理）

- **用户故事**：作为用户，我要在消息流里看到 AI 用了什么工具、正在执行还是已完成、结果是什么（联网搜索还附来源引用），以便理解并核验回答。

### REQ-033 上下文组装迁服务端〔CHG-007〕

- **用户故事**：作为用户，我要多轮上下文规则在服务端统一执行，以便 agent 回合（含工具结果注入）组装正确，且后续演进（压缩、记忆）不依赖我浏览器里的前端版本。
- **描述**（CHG-007 新增，基线 req-baseline-v5）：上下文组装规则**照搬现状**：系统提示词（如有，REQ-008）+ 最近 20 轮（最多 40 条消息）；组装主体由前端迁至服务端 agent 运行时，前端不再组装与上传历史（请求仅含本条消息 + 会话 id；**另有可选第三字段 `system_prompt`**——全局系统提示词存前端 localStorage、随回合上传，见 design-iter-13 §4.2 基线后补注；2026-08-18 随 design-iter-14 基线 spec 触点同步此句，QA OBS-3 闭环）。v1/v2 消息先归一化再计入窗口（一条消息即一轮的一半，不因 blocks 拆分改变「轮」的边界）。回合内的工具调用/结果注入当轮上下文，**不占用** 20 轮窗口。组装器输入输出单点收敛，为 B2 压缩预留演进接口。
- **主流程**：
  1. 前端 POST 本条消息 + session_id（请求体无历史数组）
  2. 服务端取该会话全部消息 → 归一化（v1/v2 统一展开）→ 截取系统提示词 + 最近 20 轮 → 组装 messages
  3. 上游请求体由此产生（等价性验收锚点）；回合内每步在上轮基础上追加 tool 消息后重组
- **异常分支**：会话消息不足 20 轮 → 全量携带；超 20 轮 → 截断（被截轮次完整保留在库与界面——现状口径不变）；会话不存在或属他人 → 404/403（沿复合主键归属隔离）；会话 corrupted（messages 缺失）→ 沿现有「无法读取」口径，不参与组装。
- **验收标准（可判定）**：
  1. 〔原表 6〕组装等价：同一会话（同消息集）迁移前后产生的上游请求体逐字段等价（system 首位 + 最近 20 轮；pytest，MockTransport 捕获比对）
  2. 第 30 轮请求体仅含最近 20 轮（REQ-002 验收的服务端化口径，pytest）
  3. 前端不再上传历史：回合端点请求体不含历史消息数组（vitest 断言请求载荷形状）
  4. 工具回合后的窗口边界正确：含工具回合的会话，后续组装窗口与纯文本会话同构（pytest）
- **优先级**：P0（CHG-007 建议，CEO 已批准）｜**批次**：A1（iter-13 候选）
- **涉及页面**：不涉及（数据层）

### REQ-034 配额语义改「按回合」〔CHG-007〕

- **用户故事**：作为服务部署者，我要配额按回合计量而 token 成本如实累计，以便用户侧规则简单可解释、服务端成本口径真实、单回合滥用有步数护栏兜底。
- **描述**（CHG-007 新增，基线 req-baseline-v5）：30/500/2000 的语义由「每自然日对话请求数」改为「**每自然日对话回合数**」（一回合 = 一次用户发送触发的完整 agent 过程，含其全部内部上游调用；数值 30/500/2000 与管理员按用户覆盖机制沿用，见 REQ-024）。回合内每次上游调用的 usage（stream_options.include_usage，现状已旁路采集）逐次累加、回合结束落 usage_daily；步数上限是回合内护栏、不占配额。计算规则全文与数值示例见 changes.md CHG-007 内容 4.4。usage_daily 落库方式已定（design-iter-13 定夺）：新增 turns 列、历史数据不回填。注册限频（每 IP 每日 3）不变。DEF-028 随本条销账（联动 REQ-024/025 改写）。
- **主流程**：
  1. 回合受理：查当日该用户当前档位配额 → 不足即 429（零上游调用）→ 充足则回合计数 +1（先查后计点位沿用）
  2. 回合内逐次上游调用累计 tokens（usage 帧旁路，现状机制沿用）
  3. turn.end 时 usage_daily 落库：该日该用户该模式回合数 +1、tokens + 本回合累计值
- **异常分支**：
  - 步数上限截停：已计 1 回合、tokens 计已发生调用的累计值（不因截停清零）
  - 断连取消：已抵上游则计 1 回合、零上游调用不计（design-iter-13 定夺——与「配额不足不抵达上游」的公平性边界一致）
  - 回合中途服务重启/崩溃：回合计数已落（先查后计），tokens 计已落部分，缺失不补造（铁律 5，admin 面板缺失时段沿用「不估算」口径）
  - 旧透传端点（窗口期老客户端）：1 次请求 = 1 次上游调用，按 1 回合计（两入口配额同源同语义）
- **验收标准（可判定）**：
  1. 〔原表 5〕配额设 5 的账号：第 6 回合收到配额提示（429 quota_exhausted 语义），服务端日志证明该回合零上游调用（seen 取证沿用）
  2. 〔原表 10〕一回合 3 次上游调用（MockTransport 编排）：usage_daily 该日该用户回合 +1、tokens = 三次调用 usage 之和（pytest 数值断言，如 1200+1500+900=3600）
  3. max_steps=2 截停的回合：计 1 回合、tokens 计前 2 步已发生值（pytest）
  4. 既有 test_quota 16 用例语义迁移后全绿（限频/边界/档位联动/熔断/次日重置/不抵达上游，数值断言同构改回合）
- **优先级**：P0（CHG-007 建议，CEO 已批准）｜**批次**：A1（iter-13 候选）
- **涉及页面**：不涉及（提示复用 REQ-007 体系；统计口径见 REQ-025）

### REQ-035 联网搜索工具〔CHG-007〕

- **用户故事**：作为用户，我要问时效性问题时（今天的热点、最新版本号）AI 自动联网搜索并给出来源引用，以便答案不过时、可核验。

  3. 结果组装：截断至大小上限、整理为「结果摘要 + 来源列表（标题/URL/片段）」文本
  4. tool.result 回填 → 模型综合生成带引用标记的回答 → 前端渲染引用来源卡（design-iter-14）

  - 搜索结果为空：模型据空结果如实回答「未搜到相关内容」，不编造来源
  - 结果超限：网关截断（模型只见截断后内容）

  1. 〔原表 11〕时效性问题（预置样例）回答含可见工具步骤与引用来源（真实 Chrome 走查留档）
  2. 〔原表 12-a〕搜索 API 失败/超时（假搜索端点）→ 回合降级直答不崩（pytest + 走查）
  3. 〔原表 12-b〕admin 关闭搜索 → 注册表无 search、上游请求 tools 定义不含 search（pytest 断言 payload）
  4. 〔原表 9 实例化〕出网仅搜索 API 域：目标改为内网/他域 → 零连接（pytest）

- **优先级**：P1（CHG-007 建议，CEO 已批准——依赖第三方选型与 key 归属，保留排期弹性）｜**批次**：A2（iter-14 候选）
