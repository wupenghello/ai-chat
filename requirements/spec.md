## 1. 产品概述

ai-chat 为单个用户提供一个简洁可用的 AI 对话界面：通过调用第三方大模型 API，支持流式输出的多轮连贯对话，会话在本地保存、可随时恢复，并提供系统提示词设置。本产品不做账号体系与多用户，不做 RAG/知识库（均为后期边界，见暂缓想法池）。第一版目标是"最小 MVP"：砍到骨头的产品闭环——能对话、能记住上下文、能保存恢复会话。

**架构决策（2026-08-15 CEO 拍板）**：MVP 采用**纯前端应用直连第三方 API，不自建后端**。API 供应商做成可配置项（按 OpenAI 兼容协议，可配置 base URL + 模型名 + API key），用户大概率使用 DeepSeek 或 GLM。API 密钥由用户在设置页自填、仅存浏览器本地（详见 REQ-014 与非功能需求安全条款）。自建代理后端与账号体系、RAG 一并列入暂缓想法池，后期纳入时走需求变更流程。

## 2. 用户故事

### REQ-001 发送消息并流式接收回复

- **用户故事**：作为用户，我要在输入框输入文本并发送，以便获得 AI 的回答，且回答以流式方式逐步显示，以便我不必等待完整生成。
- **描述**：对话主界面的核心交互：文本输入框 + 发送按钮 + 消息展示区。AI 回复以打字机效果流式渲染。
- **主流程**：
  1. 用户在输入框输入文本（支持多行）
  2. 点击发送按钮或按回车（Shift+Enter 换行）
  3. 用户消息立即显示在消息区，输入框清空
  4. 消息区出现该会话的 AI 回复气泡，内容随流式返回逐步渲染
  5. 流式结束后，回复气泡标记为完成
- **异常分支**：
  - 输入为空或仅含空白字符：发送按钮不可用，点击无动作，不发出请求
  - 发送时上一条回复仍在生成中：禁用发送（或提示等待），不并发请求
  - 网络失败 / API 报错 / 超时：该 AI 气泡显示明确错误提示（含错误类型），并提供"重试"入口；用户已发出的消息保留在消息区，不丢失
  - 流式中断：已收到的部分内容保留显示，并标注"生成中断"
- **验收标准**：
  - 输入"你好"并发送后，1 秒内用户消息出现在消息区
  - 收到首个流式数据块后 200ms 内，回复气泡开始显示内容
  - 回复过程中界面无需整体刷新，历史消息不重排闪烁
  - 发送空字符串 / 纯空格：无请求发出，无新气泡产生
  - 断网状态下发送：3 秒内出现含错误提示的气泡，且提供重试；重试成功后正常流式显示
- **优先级**：P0（MVP）
- **涉及页面**：待设计师产出

### REQ-002 多轮上下文记忆

- **用户故事**：作为用户，我要 AI 记住我在本会话中说过的话，以便进行多轮连贯对话而不必每次重复背景。
- **描述**：每次请求将本会话的历史消息一并发给 API，使 AI 回复与上文连贯。上下文组装规则：**系统提示词（如有，见 REQ-008）+ 最近 20 轮（最多 40 条消息）**；更早轮次仅存本地，不参与请求。
- **主流程**：
  1. 用户发送第 N 条消息
  2. 系统按上述规则组装请求上下文（系统提示词 + 最近 20 轮）
  3. AI 回复与上文指代、事实保持连贯
- **异常分支**：
  - 会话消息超出 20 轮：自动截断，仅携带最近 20 轮，不报错、不中断对话；被截断轮次仍完整保留在本地与界面中
- **验收标准**：
  - 连续对话测试：第 1 轮告知"我叫小明"，第 5 轮问"我叫什么"，AI 回答包含"小明"
  - 第 10 轮对话的请求中可观测到包含此前轮次的消息（通过请求体或日志验证）
  - 第 30 轮对话的请求体中仅包含最近 20 轮消息，对话仍正常进行，无报错；界面仍可滚动查看全部 30 轮
- **优先级**：P0（MVP，立项书成功标准 1）
- **涉及页面**：不涉及（数据层逻辑，界面表现归 REQ-001/004）

### REQ-003 新建会话

- **用户故事**：作为用户，我要一键新建一个空白会话，以便开始一个与之前话题无关的新对话。
- **描述**：提供"新建会话"入口，创建空会话并切换为当前会话。
- **主流程**：
  1. 用户点击"新建会话"
  2. 系统创建空会话（自动命名，见 REQ-009），切换到空白对话界面
  3. 新会话出现在会话列表顶部
- **异常分支**：
  - 当前会话回复正在生成中：**中断生成**（CEO 已拍板），原会话中该回复保留已生成部分并标注"生成中断"，不后台继续
- **验收标准**：
  - 点击"新建会话"后 300ms 内界面切换为空白对话界面，输入框可输入
  - 新会话在会话列表可见，刷新页面后仍存在（依赖 REQ-006）
  - 连续新建 10 个会话，列表完整显示 10 条，无重复 ID
  - 生成中点击新建：原会话的回复停止增长且标注"生成中断"，新会话界面立即可输入
- **优先级**：P0（MVP）
- **涉及页面**：待设计师产出

### REQ-004 查看历史会话并切换

- **用户故事**：作为用户，我要看到我的历史会话列表并点击任一会话恢复查看，以便回顾和继续之前的对话。
- **描述**：侧边（或顶部）会话列表展示全部历史会话，点击切换到该会话并完整展示其消息。生成中切换会话**不中断**：原会话在后台继续流式生成，完成后切回可见完整回复（CHG-001，2026-08-15 修改；原"中断并标注"仅保留给"生成中新建会话"场景，见 REQ-003）。
- **主流程**：
  1. 用户打开应用，会话列表按最近活跃时间倒序展示
  2. 点击任一会话
  3. 消息区加载该会话全部消息并定位到最新一条
- **异常分支**：
  - 无任何历史会话：显示空状态引导（如"点击新建会话开始对话"），不显示空白列表
  - 会话数据损坏 / 读取失败：该会话在列表中标注"无法读取"，不影响其他会话的展示与使用
  - 切换时原会话正在生成：不中断，原会话后台继续生成（CHG-001）；切回时可看到已生成的部分或完整回复
- **验收标准**：
  - 含 50 个会话、每会话 20 轮消息时，点击会话到消息完整渲染 < 1 秒，滚动到最新消息
  - 空态：无会话时显示引导文案，不出现 JS 报错
  - 切换会话后再切回，消息内容与切换前一致
- **优先级**：P0（MVP，立项书成功标准 2）
- **涉及页面**：待设计师产出

### REQ-005 删除会话

- **用户故事**：作为用户，我要删除不需要的会话，以便保持会话列表整洁。
- **描述**：会话列表项提供删除操作，需二次确认以防误删。
- **主流程**：
  1. 用户在某会话上触发删除
  2. 弹出确认提示
  3. 确认后该会话从列表和本地存储中移除
  4. 若删除的是当前会话，自动切换到列表中最近的会话；若已无会话，显示空态
- **异常分支**：
  - 取消确认：会话保留，无任何变化
  - 删除后本地存储写入失败：界面提示删除失败，会话保留
- **验收标准**：
  - 删除必须经确认，未确认前会话不被移除
  - 删除后刷新页面，该会话不再出现（本地存储中确实清除）
  - 删除当前会话后界面不出现空白或报错，按上述规则切换
- **优先级**：P0（MVP）
- **涉及页面**：待设计师产出

### REQ-006 会话本地持久化与恢复

- **用户故事**：作为用户，我要我的会话在关闭应用后依然保存，以便下次打开继续，不丢任何内容。
- **描述**：所有会话（含消息内容）持久化在浏览器 **IndexedDB**（CEO 已拍板），无服务端存储。
- **主流程**：
  1. 每轮对话完成（用户消息 + AI 完整回复）后写入 IndexedDB
  2. 用户关闭浏览器/标签页后重新打开
  3. 会话列表与各会话消息完整恢复
- **异常分支**：
  - IndexedDB 写入失败（如隐私模式限制、空间满）：界面给出提示，会话在内存中保留，本次会话不中断
  - 存储数据版本不兼容（升级后结构变化）：提供降级读取或明确提示，不静默丢失全部数据
- **验收标准**：
  - 完成一次对话后关闭标签页再打开，该会话与消息内容逐字保留
  - 流式生成中途刷新页面：已完成的轮次保留，未完成的 AI 回复标注"生成中断"且不出现半条损坏消息
  - 本地写入 20 个会话后，应用仍可正常启动与读写
- **优先级**：P0（MVP，立项书成功标准 2）
- **涉及页面**：不涉及（数据层）

### REQ-007 调用异常与降级提示

- **用户故事**：作为用户，我要在 AI 服务出错时得到人话的提示和可行的下一步，以便知道是等待、重试还是检查配置。
- **描述**：对第三方 API 的常见错误（网络失败、超时、401 密钥无效、429 限流、5xx 服务异常）给出区分化的提示文案与建议动作。
- **主流程**：
  1. 请求失败时，按错误类型映射为用户可读的提示（如"服务暂时不可用，请稍后重试"）
  2. 可重试的错误（网络/超时/5xx/429）提供"重试"按钮，重试复用原消息
- **异常分支**：
  - 401/403（密钥无效/无权限）：提示"API 密钥无效，请检查设置"，并提供**跳转到设置页（REQ-014）**更新密钥的入口
  - 429：提示稍后重试，不自动连发重试
  - 未配置 API 密钥即发送消息：不发出请求，提示并引导前往设置页
- **验收标准**：
  - 模拟网络断开、超时、429、401 四种错误，分别显示四种不同的提示文案，无技术性报错堆栈直接暴露给用户
  - 401 提示中包含可点击的设置页入口，点击后打开设置页（REQ-014）
  - 每种可重试错误的"重试"点击后重新发起请求，成功后正常流式显示
  - 错误提示在 3 秒内出现（不含网络层自身的超时等待）
- **优先级**：P0（MVP，立项书约束"需考虑降级与错误提示"）
- **涉及页面**：待设计师产出

### REQ-008 系统提示词设置

- **用户故事**：作为用户，我要为会话设置系统提示词（如"你是一个简洁的翻译助手"），以便定制 AI 的角色与风格。
- **描述**：提供设置入口，可编辑系统提示词；系统提示词作为上下文第一条随每次请求发送（参与 REQ-002 的上下文组装，不受 20 轮截断影响）。**优先级 CEO 已拍板为 P1，不进 MVP。**
- **主流程**：
  1. 用户打开设置，输入系统提示词并保存
  2. 后续请求将该提示词置于上下文首位
  3. AI 按该角色设定回复
- **异常分支**：
  - 留空：按无系统提示词正常请求，不报错
  - 修改已有会话的系统提示词：只影响之后的轮次，历史消息不变
- **验收标准**：
  - 设置"回复只用英文"后，同一会话内 AI 回复为英文；清除设置后恢复默认行为
  - 系统提示词随会话持久化，刷新后仍生效
  - 会话超过 20 轮时，请求体中系统提示词仍在首位（不被截断）
- **优先级**：P1（CEO 已确认）
- **涉及页面**：待设计师产出

### REQ-009 会话自动命名

- **用户故事**：作为用户，我要每个会话有可辨认的标题，以便在列表中快速找到目标会话。
- **描述**：新会话默认以时间或首条用户消息摘要命名；可自动（用首条消息前 N 字）实现，无需额外调用 AI。
- **主流程**：
  1. 新建会话，标题初始为"新会话"或时间戳
  2. 用户发出第一条消息后，标题更新为该消息前 20 字（截断加省略号）
- **异常分支**：
  - 首条消息为空：不更新标题（发送已被 REQ-001 拦截，不会发生）
- **验收标准**：
  - 发送"帮我写一封请假邮件，理由是家里有事"后，列表中该会话标题为其前 20 字
  - 同一用户并发多会话时，标题与内容对应正确
- **优先级**：P1
- **涉及页面**：待设计师产出

### REQ-010 停止生成

- **用户故事**：作为用户，我要在 AI 回复过程中随时点击"停止"，以便中断无用或过长的回答并立即继续提问。
- **描述**：流式生成中，发送按钮切换为"停止"；点击后终止流，保留已生成部分。
- **主流程**：
  1. 流式生成中用户点击"停止"
  2. 流被终止，已生成内容保留并标注完成
  3. 输入框恢复可用
- **异常分支**：
  - 停止请求发出时流已恰好结束：按正常结束处理，不报错
- **验收标准**：
  - 点击停止后 200ms 内停止渲染新内容，输入框可再次发送
  - 已生成部分保留且随会话持久化
- **优先级**：P1
- **涉及页面**：待设计师产出

### REQ-011 Markdown 渲染与代码块复制

- **用户故事**：作为用户，我要 AI 回复中的列表、表格、代码块正确渲染，并能一键复制代码，以便直接使用回答内容。
- **描述**：AI 回复按 Markdown 渲染；代码块带语言标签和复制按钮。
- **主流程**：
  1. AI 回复含 Markdown 语法
  2. 渲染为对应富文本；代码块右上角显示"复制"按钮
  3. 点击复制后按钮短暂变为"已复制"
- **异常分支**：
  - 回复为纯文本：按普通段落渲染，不出错
- **验收标准**：
  - 含标题/列表/表格/代码块的回复渲染后结构与语法对应
  - 点击复制后，系统剪贴板内容与代码块原文逐字一致
- **优先级**：P1
- **涉及页面**：待设计师产出

### REQ-014 API 供应商与密钥可配置

- **用户故事**：作为用户，我要在设置页配置 API 供应商地址（base URL）、模型名和 API 密钥，以便使用 DeepSeek、GLM 等 OpenAI 兼容服务并自主更换供应商与模型。
- **描述**：MVP 不绑定单一供应商，按 OpenAI 兼容协议（chat completions + 流式）实现，供应商三要素（base URL / 模型名 / API key）全部为设置页可配置项，仅存浏览器本地，无服务端。
- **主流程**：
  1. 用户打开设置页，填写 base URL、模型名、API key 三项
  2. 点击保存，配置写入浏览器本地存储，界面提示保存成功
  3. 后续所有对话请求使用该配置
  4. 用户可随时修改任一项并保存，立即生效于下一次请求
- **异常分支**：
  - 三项任一为空时保存：提示对应必填项，不写入不完整配置
  - 未完成配置即发送消息：不发出请求，提示"请先完成 API 配置"并引导前往设置页
  - key 无效（401/403）：由 REQ-007 的错误提示引导回设置页更新
- **验收标准**：
  - 分别配置 DeepSeek 与 GLM（各填一次 base URL/模型名/key），均可完成一次流式对话，证明协议兼容与可切换
  - 配置保存后刷新页面，三项配置均保留
  - 设置页提供"清除密钥"入口；点击后本地存储中检索不到 API key 残留（可验证）
  - API key 绝不出现在代码仓库中：`git grep` 对仓库全量历史检索不到任何真实 key；密钥仅存于浏览器本地存储
- **优先级**：P0（MVP，纯前端直连方案下密钥配置是产品闭环的前提）
- **涉及页面**：待设计师产出

### REQ-015 消息编辑与重新生成（regenerate）

- **用户故事**：作为用户，我要编辑已发送的某条消息并重新生成后续回复，以便纠正错误或换个说法重试，而不必重开对话。
- **描述**：用户可对历史中某条「用户消息」进入编辑态，修改后重新发送；系统删除该条及其后全部消息，从该条起按 REQ-002 规则重建上下文并流式生成新回复。
- **主流程**：
  1. 用户在任一条用户消息上触发「编辑」
  2. 该消息进入可编辑态（原文本回填或就地编辑）
  3. 用户修改并确认
  4. 系统删除该条及其后所有消息，从该条起重新组装上下文（系统提示词 + 最近 20 轮）并流式生成新回复
- **异常分支**：
  - 编辑后文本为空或仅含空白：确认不可用，不发请求
  - 生成中编辑历史消息：允许编辑；确认编辑时**中断当前正在生成的回复**（该回复保留已生成部分并标注「生成中断」，与 REQ-003 语义一致），随后从编辑点重新生成
  - 持久化写入失败：界面提示，消息在内存中保留，不静默丢数据
- **验收标准**：
  - 编辑第 2 轮消息后，第 2 轮及其后消息被新回复替换，第 1 轮及其历史不变
  - 重新生成的请求体中，编辑点之前的历史完整保留、之后的历史不再出现（可观测请求体）
  - 编辑后刷新页面，编辑结果持久化
  - 生成中编辑历史消息并确认：原回复停止增长并标注「生成中断」，从编辑点起出现新回复
- **优先级**：P1
- **涉及页面**：待设计师产出

### REQ-016 会话搜索

- **用户故事**：作为用户，我要按关键词搜索历史会话，以便快速找到目标会话。
- **描述**：侧栏会话列表提供搜索框，输入关键词实时过滤出「标题或消息正文含关键词」的会话（本地遍历 IndexedDB，不调 AI API）。
- **主流程**：
  1. 用户在侧栏搜索框输入关键词
  2. 列表实时过滤为匹配会话（标题命中优先排序）
  3. 点击结果切换到该会话
- **异常分支**：
  - 无匹配：显示「无匹配会话」空态，不显示空白
  - 关键词为空：恢复完整列表
  - 数据损坏会话：仍显示「无法读取」，搜索不被其拖崩
- **验收标准**：
  - 输入正文中某词后 500ms 内返回标题或正文含该词的会话列表
  - 点击搜索结果能正确切换到目标会话
- **优先级**：P2
- **涉及页面**：待设计师产出

### REQ-017 暗色主题

- **用户故事**：作为用户，我要切换暗色主题，以便夜间使用不刺眼。
- **描述**：提供明/暗主题切换，暗色下全界面配色适配；遵循 design-system 暗色令牌（前置：新增暗色令牌）。
- **主流程**：
  1. 用户在设置/顶栏切换主题
  2. 界面颜色立即切换为暗色
  3. 选择持久化，下次打开保持
- **异常分支**：
  - design-system 尚无暗色令牌：需先新增暗色令牌再实现（前置依赖）
- **验收标准**：
  - 切换后 200ms 内全部界面颜色生效，无硬编码亮色残留
  - 刷新后主题保持
  - 暗色下正文文字对比度满足 AA（≥4.5:1）
- **优先级**：P2（前置：design-system 暗色令牌）
- **涉及页面**：待设计师产出

### REQ-018 多供应商档案一键切换

- **用户故事**：作为用户，我要保存多套 API 供应商配置并一键切换，以便在 DeepSeek/GLM 间随时切换而不用手改。
- **描述**：扩展 REQ-014，从单套配置扩展为多套档案（每组 base URL + 模型名 + API key），列表选择当前生效档案。
- **主流程**：
  1. 设置页新增「添加供应商档案」
  2. 填写并保存多套档案
  3. 选择其中一套为当前生效
  4. 后续请求使用当前生效档案
- **异常分支**：
  - 档案任一必填项为空：不保存，提示必填
  - 切换档案时正在生成：**当前这轮用旧档案跑完，切换自下一次请求生效**（与 CHG-001「切换不中断」语义一致，不打断生成）
  - 删除当前生效档案：提示需先切换到其他档案
- **验收标准**：
  - 保存 DeepSeek + GLM 两套档案后，一键切换即可用对应档案完成流式对话
  - 当前生效档案持久化，刷新后保持
  - 生成中切换档案：当前回复用旧档案完整生成，下一条消息用新档案发出
- **优先级**：P2（REQ-014 增强）
- **涉及页面**：待设计师产出

### REQ-019 版本切换

- **用户故事**：作为用户，我要在编辑/重新生成后切换回之前的回复版本，以便对比或恢复旧回答。
- **描述**：编辑历史消息或重新生成后，系统保留被替换的旧分支；消息下方操作栏提供「切换版本」入口，在新旧分支间互换（参考 DeepSeek 版本导航，CHG-003）。
- **主流程**：
  1. 用户编辑某条消息并重新生成（REQ-015）
  2. 被替换的旧分支归档保留（Session.branches，按 forkId 索引）
  3. 用户在消息下方点「切换版本」，视图在新旧分支间互换，可反复切换
- **异常分支**：
  - 无旧分支（未编辑过）：不显示切换入口
  - 切换时正在生成：编辑确认时已中断当前生成（REQ-015），无并发冲突
- **验收标准**：
  - 编辑消息重新生成后，原回复可通过「切换版本」找回，且可再次切回新回复
  - 刷新页面后，切换能力与当前显示版本保持一致（branches 随会话持久化）
- **优先级**：P1
- **涉及页面**：待设计师产出

|------|------|

| 安全 | API 密钥由用户在设置页自填，仅存浏览器本地（IndexedDB/localStorage），**绝不硬编码在前端代码、绝不提交进 git 仓库**；设置页提供清除密钥入口；密钥失效（401/403）时提示并引导更新；浏览器本地会话数据不做加密（MVP 边界，已接受） |
| 可观测 | 错误场景对用户有明确提示（REQ-007）；开发阶段可通过日志/网络面板观测请求与上下文组装（支撑 REQ-002 验收） |
