### T2 后端个人用量端点（M）

**工作项**：

1. **GET /api/usage/summary?days=N**：本人 user_id 从会话凭证解析（HttpOnly Cookie，沿既有鉴权面）；`days ∈ {7, 30}` 校验（默认 7，越界 422）；返回形状 = `{ window, price: {configured, input_per_mtok, output_per_mtok, cache_hit_per_mtok}, today: {...同 /api/quota 口径数字}, daily: [{day, turns, tokens_prompt, tokens_completion, tokens_total, cache_hit_tokens, cache_miss_tokens, mode_unified/self 分布, cost_total, ...}] }`——形状细节按 design-iter-21 §API 定案（设计稿承载，T1 定死）。
2. **聚合查询**：telemetry 按 user_id × day 聚合（回合数 = distinct turn_id 口径按设计稿定案；endpoint 加法区分 turn/research 是否分列，设计稿定案）；与 admin 端点同构 SQL 体例；user_id+day 查询性能核实（90 天窗口单用户量级极小，预期无风险，verify 留档）。
3. **成本体例**：`_cost6` 复用或同构提取（admin.py L392-401 → 公共函数或独立实现同体例，实现级决策登记 verify）；仅 unified 计费（LLM 行 + compress 行 tokens_prompt 输入计价——REQ-038 定夺⑥口径）；单价未配置 → 全 null 不估算。
4. **pytest 新增**（预估 12~18 用例）：聚合一致性（与 telemetry 表抽样比对）/ 跨用户隔离（A 查 B → 403 或空，不泄露存在性）/ 未配置单价 null 面 / 空窗口态 / days 越界 422 / 未登录 401；test_quota 17 例零改动复跑（REQ-052 验收 5 红线）。
5. **零改动面**：telemetry.py 写入点、db.py schema、quota.py、既有全部端点形状。

**判定依据**：planning.md §2 M 定义「一个模块内的完整功能」：单端点 + 聚合查询 + 异常分支四类。类比：iter-15 B1 遥测聚合端点（test_admin_telemetry 8 例体量）定档；本次聚合面相似 + 隔离面新增，取 M 有余。

**验收标准**（REQ-052 验收 1/2/3/4/5 后端面）：

1. 普通用户可查本人近 7/30 天每日回合数与 token 数，与 telemetry 表抽样比对一致（机器采集）；
2. 费用估算仅 mode='unified' 计入、体例与 admin 遥测卡同源（同单价同算法）；
3. 用户 A 的接口取不到用户 B 的用量（403/隔离用例）；
4. 单价未配置 → 费用字段全 null（不估算不编造，铁律 5）；
5. test_quota 17 例零改动复跑全绿 + /api/quota 形状零回退；
6. pytest 存量 347 零回退 + 新增全绿（`make check` 实测口径）。
